01 / E3 COLOR SPACE

색공간 행에서 실제 위젯까지

E3의 색공간 행을 선택한 합성 상태에서 이벤트 12를 전달하면 원본 핸들러가 색공간 모드 0x53을 요청합니다. 모드 진입과 26개 GUI 컴포넌트 생성, 초기 활성화를 실행한 뒤 두 선택지 사이의 키 분배와 포커스 콜백을 추적했습니다. 물리 버튼 스캔과 전체 RTOS 큐는 이번 실행 범위에 포함하지 않았습니다. [U1: findings.entry·event·focus]

공식 설명서 p.20는 이 항목을 E3의 13. Color Space로 명시하고 기본값을 sRGB로 표시합니다. 이 보고서는 촬영 설정 화면을 다루며 재생 중 RAW 현상 화면과 구분합니다.

02 / LIVE VALUE AND ROLLBACK

선택은 즉시 쓰고, 취소는 복원한다

화면을 열면 설정 ID 0xd7의 현재값을 백업합니다. 그 값에 맞는 선택지가 활성화됩니다. 활성화는 같은 값이라도 setter를 호출합니다. 선택을 바꾸면 설정값이 바로 바뀌므로 이 화면의 백업을 별도 보류값으로 해석할 수 없습니다. [U1: findings.state]

확정 이벤트 8은 추가 설정 쓰기 없이 부모 모드 0x23을 요청합니다. 취소 이벤트 3은 백업값을 다시 쓴 뒤 종료를 요청합니다. 두 방향의 변경·확정과 변경·취소를 실행하고 두 값 각각에서 같은 값 확정도 실행했습니다. 다시 열었을 때 포커스는 복원된 값 또는 유지된 값에 맞았습니다. [U1: replay.cases]

03 / SETTING BANK AND FILE-NAME POLICY

설정 RAM과 하위 DCF 호출을 따로 관측한다

설정 setter와 getter는 bank 0의 동일한 바이트를 사용합니다. 호출 기록과 실제 sb 쓰기를 따로 세어 각각 18회를 확인했습니다. 인접한 15바이트는 보존됐습니다. 이것은 합성 RAM의 변경 증거이며 영속 저장이나 전원 재시작 후 유지 여부를 확인한 결과는 아닙니다. [U1: findings.storage·replay]

DataHelper_SetUserData(0xd7, value) 0x80430d08
→ 0x8010ec04 → UserDataInfo_SetMenuValue 0x80127cfc
→ bank 0: 0x8153c288 + 0x6e4 + 0xd7 = 0x8153ca43
backup byte = 0x80bed850; focus record = 0x80b63168

포커스 변경 뒤에는 원본 DCF 접두사 선택 함수가 설정을 다시 읽고 하위 API를 호출합니다. 취소의 복원 함수 자체에는 이 호출이 없습니다. 종료 후 다른 경로가 접두사를 갱신할 수 있으므로 이 사실만으로 실제 파일명이 이전 선택에 머문다고 단정하지 않았습니다. [U1: findings.naming]

공식 설명서는 sRGB의 파일명 예를 IMGPxxxx.JPG, AdobeRGB를 _IMGxxxx.JPG로 제시합니다. 여기서는 이 의미와 원본 접두사 선택 경로를 대조했으며 실제 파일을 생성하지 않았습니다. [설명서 p.66]

04 / TEXT AND FOCUS

문자열 리소스와 포커스 표시의 연결

색공간 화면의 테이블에서 제목·선택지·안내·확정·취소의 문자열 리소스 포인터를 찾았습니다. 선택 캔버스의 활성화는 표식과 안내 컴포넌트의 가시성을 바꾸는 코드로 이어집니다. 재실행은 컴포넌트 생성과 포커스를 확인했지만 가시성 값이나 최종 LCD 픽셀은 직접 비교하지 않았습니다. [U1: rendering]

05 / K-3 MARK III COMPARISON

공통 동작 이름과 원본 상태 모델을 구분한다

K-3 Mark III 자료의 색공간 요청·설정 경로와 의미를 대조했습니다. 공통 UI 계약의 선택·확정·취소는 설계용 동작 이름입니다. 제안된 ‘선택은 보류값만 변경하고 확정 때 한 번 쓰기’는 Q7 원본의 즉시 쓰기·취소 복원과 다릅니다. 기종 간 이벤트 번호, 설정 ID와 객체 배치를 같다고 가정하지 않았습니다.

06 / REPRODUCIBILITY AND LIMITS

원본 코드 실행과 모델 경계

원본 입력부터 물리 화면까지 연결하려면 스위치 스캔, 이벤트 큐 소비, 비동기 화면 갱신과 문자열 래스터 출력이 더 필요합니다. 이번에는 8개 외부 경계를 모델로 대체했습니다. 카메라 조작, 저장매체 기록과 펌웨어 설치는 수행하지 않았습니다. [U1: limitations]

작업자 실행과 조정자의 독립 실행에서 6개 사례·18회 setter 호출·18회 바이트 쓰기가 일치했습니다. 원본 펌웨어에서 180개 명령·데이터 word와 56개 함수 범위의 해시·전이를 다시 계산했습니다. 함수 범위는 복구된 sidecar의 다음 주소까지이며 typed ELF 크기로 확정한 것이 아닙니다.

python tools/check_colorspace_ui.py <pinned-analysis.elf> --output <new-result.json>
