색공간 글자의 가장자리 처리

Q7 v1.01의 원본 글리프 함수에 좌상단 좌표 (−9, −12)를 주면, 화면 첫 행에 들어오는 픽셀 8개도 건너뜁니다. 개별 픽셀의 가로 좌표를 검사하기 전에 글리프 행의 시작 주소를 확인하기 때문입니다.

행 시작 주소를 먼저 검사합니다

기존 48×48 축소 그리기가 사용한 LatinFont에서 Color Space의 sRGB 행 첫 글자(내부 코드 84)를 골랐습니다. 64×48 셀의 요청 크기는 48×48입니다. 이 글리프의 실제 폭은 24에서 18로 줄고 높이는 48을 유지합니다. 합성 표면은 736바이트 피치, 176행, 8비트 인덱스로 준비했습니다.

원본 열은 (j × 87381 + 43690) >> 16입니다. 역스텝 87381은 floor(24 × 65536 / 18), 43690은 그 절반을 버림한 값입니다. 먼저 이 식으로 샘플을 고르므로, 왼쪽이나 위가 잘려도 남은 부분의 첫 픽셀을 기준으로 다시 샘플링하지 않습니다. 이 설정에서 코드 1·2·3은 각각 인덱스 2·1·3으로 매핑됩니다.

마지막 조건에서 원본 글리프의 12행은 화면 0행에 닿습니다. 좌표 교집합만 검사하면 화면 0행의 X=0…7에 인덱스를 써서 전체 쓰기가 228회가 됩니다. 원본은 해당 글리프 행의 시작 주소가 프레임보다 9바이트 앞에 있어 이 여덟 곳의 초기 인덱스 0xA5를 유지했습니다.

각 실행의 864개 소스 열과 2비트 코드, 쓰기 순서와 인덱스, 129,536바이트 표면 전체가 독립 계산과 일치했습니다. 앞뒤 16바이트 보호값을 확인했습니다. 독립 검토에서 획이 걸친 좌상단 1건을 다시 실행해 기록 전체가 일치했고, 나머지 6건은 저장된 원본 실행 기록을 독립 계산과 대조했습니다. 사례별 해시와 원본 구간

준비 단계와 원본 실행 범위

기존 시험과 같은 합성 ID 0·17 연결에서 원본 글꼴 선택과 속성 설정을 실행했습니다. 준비 단계의 미디어·FileX·할당·버퍼 메타데이터·캐시는 모델이 응답합니다. 준비된 컨텍스트에서 0x80226748에 직접 진입하면 모델 호출 없이 호스트가 넣은 반환 센티널 0x0BADF000에 도달하고 스택 포인터가 복귀합니다. 일곱 기록에서 컨텍스트의 최종 바이트 차이는 없었습니다. 하네스는 최종 차이 검사에서 팔레트 슬롯 영역 +0x24…+0x33을 허용합니다. 글꼴과 스테이징 입력은 그대로였습니다.

실제 메뉴가 음수 좌표를 공급하는지, 다른 회전·반전·수직 배율과 보조 클리핑 비트맵이 어떻게 동작하는지, 물리 팔레트나 LCD에 무엇이 표시되는지는 확인하지 않았습니다. 이 실험은 기존 Color Space의 한 글리프와 합성 표면의 동작을 다룹니다. 원본 컨텍스트 선택과 합성 등록표의 관계

기록 검사와 단계별 재현

기록 검사에는 펌웨어와 에뮬레이터가 필요 없습니다. 원본 재현에는 Q7 v1.01 패키지와 그 패키지로 구성한 분석 ELF, 검증한 환경은 Python 3.12.3, angr 10.0.5, pyelftools 0.33입니다. CLI는 두 입력의 크기와 해시를 고정하고 패키지의 E04를 다시 디코딩해 분석 ELF의 해당 영역과 대조합니다. 원본 재현은 두 단계로 나뉘며, 내부 대조를 포함한 edges 여섯 건은 수 분이 걸립니다.

원본 패키지에서 분석 ELF 준비 
python -B tools/decode_segments.py <package> --output-dir decoded-q7
python -B tools/build_analysis_elf.py <package> --decoded-dir decoded-q7 --output analysis-q7.elf

새 로컬 경로를 사용합니다. 이 두 명령의 출력은 분석 입력이며 카메라 업데이트 파일이 아닙니다.

python -B tools/check_colorspace_clip.py check
python -B tools/check_colorspace_clip.py replay <package> <analysis-elf> --stage corner --output corner.json
python -B tools/check_colorspace_clip.py replay <package> <analysis-elf> --stage edges --output edges.json
python -B tools/check_colorspace_clip.py project edges.json corner.json --output clip-summary.json

두 단계의 전체 실행 기록을 각각 고정 해시와 비교한 뒤에만 일곱 건의 공개 요약을 만듭니다. 기존 출력 경로와 python -O 실행은 거부합니다. 공개 요약에는 원본 글꼴이나 프레임 바이트가 포함되지 않습니다. 재현 코드 · 공개 요약
