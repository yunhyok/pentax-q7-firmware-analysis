01 / FILE STAGING

원본 파일 준비는 I:\UPG_FILE.ELF 쓰기를 요청한다

UpdateFW_LoadFirmware는 먼저 설정된 경로에서 파일 크기의 하위 32비트를 읽습니다. 그 뒤 보드 버전이 3보다 작으면 로컬 경로의 드라이브를 F로, 그 외에는 E로 바꿉니다. 버전 3 사례에서는 F 경로에서 크기를 조회한 뒤 E 경로를 열었습니다. 크기에 0x2000000을 더하는 연산은 32비트 범위에서 순환하며 그 결과를 512로 나눠 올림해 파라미터 0x11e에 요청합니다. 준비·포맷·마운트 조건을 통과하면 먼저 측정한 길이만큼 읽고 I:\UPG_FILE.ELF에 쓰기를 요청합니다. 두 정상 사례의 입력과 요청 길이는 합성 96바이트입니다. [U1: staging_cases]

빈 파일, 준비값 0, 포맷·마운트 오류, 할당·열기 실패, 짧은 읽기, 쓰기 오류에서는 0을 반환했습니다. 정상 두 사례에서는 쓰기 API에 전달된 96바이트 전체가 입력과 일치했습니다. 원본 DirectFsFileWrite는 하위 FileX 상태가 0이면 1을 반환합니다. 쓰인 바이트 수는 이 반환값에서 알 수 없습니다. [U2: staging_case]

원본 입력 파일명을 담는 전역 변수에는 F:\fwdc603p.bin을 공급했습니다. 실제 파일시스템이나 대용량 버퍼 쓰기를 검증한 사례는 아닙니다.

02 / SAME NAME, DISTINCT CODE AND HANDLE

메인 콜백을 E01 로더의 콜백과 혼동하지 않는다

I43_UpgradeFlashFromCard는 AppUpgradeFlashFromCard와 BurnUfcMain을 거쳐 메인 DownloadCard에 (0xfe, 0, 1)을 전달합니다. 원본 코드는 디렉터리 모델이 제공한 upg_file.elf를 대문자 변환하고 .ELF 검색을 거쳐 선택합니다. 파일 오프셋 0x100000에서 원본 헤더 64바이트를 읽고 +0x3e의 0x55aa를 확인한 뒤 128바이트를 더 읽습니다. 이 파일 읽기와 앞선 준비 사례는 별도 상태에서 실행했습니다. [U1: bridge_cases]

원본 BurnGetHandle은 헤더의 종류 3에 대해 메인 BurnNand를 핸들 +0xca4에, 장치 함수를 +0xca8에 기록합니다. +0xcc8의 해시 플래그는 0입니다. 이어 원본 호출부가 Burn에 핸들·0x20000·콜백 테이블을 전달합니다. 이번에는 Burn 진입점에서 모델로 바꿨습니다. 메인 Burn 본문과 NAND 쓰기는 실행 범위 밖입니다. [U1: original header reads]

03 / RETURNS DO NOT HAVE ONE SHARED MEANING

동기 래퍼의 1은 하위 성공을 보장하지 않는다

Burn 모델이 0을 반환하면 DownloadCard는 1, I43 어댑터는 0을 반환했습니다. Burn 모델이 7을 반환하면 각각 0과 254가 됐습니다. 백업 플래그가 0인 동기식 UpdateFW_UpdateFirmware는 두 경우 모두 I43 상태를 로그에 넘기고 업데이트 중 플래그를 지운 뒤 1을 반환했습니다. 상위 반환값 1만으로 플래시 성공을 판단할 수 없습니다. [U1: bridge_cases 8·9]

비동기 분기는 원본 UpdateFirmwarePerform 주소를 Thread_Create 모델에 넘깁니다. 생성 모델이 0을 반환하면 래퍼도 0을 반환하지만 업데이트 중 플래그는 1로 남습니다. 생성 모델이 1을 반환한 사례에서도 플래그는 1입니다. 스레드 본문을 실행하지 않은 사례이므로 실제 스케줄링이나 작업 완료를 뜻하지 않습니다. [U1: bridge_cases 10·11]

Burn 모델이 0을 반환한 뒤 파일 닫기에 상태 7을 공급한 사례도 있습니다. 원본은 재부팅 호출을 건너뛰었지만 DownloadCard는 1, I43는 0을 반환했습니다. 닫기 실패의 실제 장치 영향은 이 모델에서 판단하지 않습니다. [U1: bridge_cases 7]

04 / K-3 MARK III COMPARISON

동일한 질문을 기종별 호출 계층에서 확인한다

고정 커밋의 K-3 Mark III 자료에서 종류 2·6·7의 래퍼는 종료 처리를 호출한 뒤 실행기의 32비트 결과를 보존합니다. 이번 Q7 동기식 경로는 하위 결과가 다른 두 사례에서 모두 1을 반환했습니다. 비교 대상의 계층과 숫자 의미가 다르므로 공통 성공 코드로 합치지 않습니다. Q7 안에서도 E01의 핸들 +0x1254와 메인의 +0xca4를 구분해야 합니다. [K1: 고정 커밋의 종료·결과 보존]
