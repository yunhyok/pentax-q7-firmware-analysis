01 / OBSERVED CALL CONTRACT, NEW STATE

MAIN 호출 인수로 새 실행을 시작했다

원본 192바이트 업데이트 헤더로 BurnGetHandle을 실행하면 MAIN BurnNand 주소 0x805dd7b8이 핸들 +0xca4에 저장됩니다. 그 핸들과 청크 크기 0x20000, sCardFunc 주소 0x805e8854를 MAIN Burn에 전달했습니다. 두 시험은 앞선 DownloadCard 실행에서 확인한 호출 인수로 각각 새로 시작합니다. [M1: call_contract·handle_fields] · [U1: 앞선 DownloadCard]

MAIN Burn의 FcuMediaInfoInit 플래그 2는 초기화 함수 내부의 cold ID 경로를 건너뜁니다. 그 뒤 FileX 열기에서 나오는 장치 요청까지 없어진다는 의미는 아닙니다. [M1: source.main_words]

02 / ORIGINAL FILEX OPEN

BurnNand보다 먼저 장치 요청에 도달한다

첫 시험에서는 설치 매체의 FileX 열기를 원본으로 실행했습니다. 드라이버 요청 4가 TlMediaInit과 TlFcuOperation을 거쳐 NAND 연산 2를 요청했습니다. Burn 진입부터 281개의 VEX 블록 이벤트 뒤 FcuNandOperationEx 주소 0x80053124에 도달해 본문 실행 전에 멈췄습니다. 이때 8바이트 ID 버퍼는 FF였습니다. 장치 응답은 공급하지 않았습니다. HostAck와 BurnNand는 아직 실행되지 않았습니다. [M1: native_open]

03 / SEPARATELY MODELED INSTALLED MEDIA

설치 헤더 요청 뒤 카드 읽기 진입을 확인했다

두 번째 시험에서는 FileX 열기에 0xf1을 반환하고 블록당 256섹터·총 262144섹터를 공급했습니다. 원본 HostAck가 1을 반환한 뒤 BurnNand가 설치 헤더를 요청했습니다. 첫 요청은 NAND 연산 6, 섹터 0, 개수 1이었습니다. 이 요청까지 134개의 VEX 블록 이벤트를 기록했습니다. 여기에 FF 예비 영역 16바이트를 공급하자 원본이 연산 4, 섹터 0, 개수 3을 요청했습니다. [M1: installed_header]

연산 4에는 패키지 오프셋 0x1000c0에서 빌린 0x600바이트를 모델 응답으로 공급했습니다. 실제 설치 매체의 데이터는 관측하지 않았습니다. 이 모델 응답 뒤 원본 카드 Read가 _fx_file_read에 0x20000바이트를 요청했습니다. 그 진입점에서 멈췄고 누적 156개의 VEX 블록 이벤트를 기록했습니다. 목적지는 합성 기본 버퍼이며 카드 파일 커서와 읽기 결과는 관측하지 않았습니다. [M1: fixture·first_card_filex]

intended_payload_offset은 시험의 의도와 이전 헤더 읽기 위치를 기록한 값입니다. 이번 FILE 구조의 실제 커서 관측값이 아닙니다. 카드 읽기 함수는 실행 결과를 받기 전에 멈춥니다. [M2: replay_mode]

04 / DISTINCT IMPLEMENTATIONS

E01의 구조 비교와 K-3의 분석 항목을 구분한다

MAIN과 E01의 BurnNand는 각각 11,040바이트입니다. 같은 위치의 2,760워드 중 2,166워드가 같고 상위 6비트 opcode 필드는 전부 같습니다. 하지만 호출 주소와 핸들 필드가 다릅니다. 이 수치는 구조 비교이며 E01의 기록·종료 재현 결과를 MAIN의 동작 증거로 옮길 수 있다는 뜻은 아닙니다. [M1: source.comparison]

K-3 Mark III의 고정 커밋은 업데이트 래퍼가 실행 결과를 보존하는 경로와 종료·자원 해제 조건을 다룹니다. 이번 Q7 분석은 그보다 아래쪽의 매체 열기와 저장장치 요청 진입을 추적했습니다. 두 기종 모두 모델 경계를 명시해야 하며 같은 반환값이나 NAND 형식·기록 순서를 가정하지 않습니다. [K1: 종료·반환의 고정 근거]

05 / BOUNDARIES AND REPRODUCTION

두 초기 구간에서 실제로 대체한 API

원본 메인 코드 98워드와 함수 후보 범위 24개, E01 코드 11워드와 타입이 있는 BurnNand 범위를 대조했습니다. 두 시험 모두 할당·뮤텍스·진단 경계를 모델로 대체합니다. 장치 연산 본문, 카드 데이터 읽기, 후속 selector 1 헤더와 섹션 맵, 기록·재부팅·복구는 미검증입니다. 다음 단계에서는 MAIN의 설치 헤더와 기하 조건을 바꿔 후속 분기를 별도로 검증합니다. [M1: limits·next_actions]
