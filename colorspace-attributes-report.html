01 / OBSERVATION AND RE-INPUT

요청은 관측했고 컨텍스트 연결은 가정했다

네 번의 원본 갱신에서 속성 72건과 텍스트 25건의 순서를 기록했습니다. sRGB 위젯 0x0191d00b는 매번 종류 7에 48·48, 종류 12에 0·0, 종류 4에 2를 전달한 뒤 텍스트를 요청했습니다. 속성의 그리기 ID는 17·18·17·18로 바뀌고 텍스트의 ID는 0입니다. 이 단계에서는 두 API를 관측 모델로 대체했습니다. [A1: refresh]

02 / NATIVE ATTRIBUTE DISPATCH

크기·간격·색 설정의 원본 분기를 실행했다

별도 실행에서 원본 속성 분기와 setter를 복원했습니다. 종류 7은 context+0x82c·0x82e에 폭과 높이를, 종류 12는 +0x824·0x828에 문자 간격 값을 씁니다. 종류 4는 색 테이블의 슬롯 1에 인덱스 2를 씁니다. 나머지 팔레트 슬롯은 시험 컨텍스트의 입력값입니다. [A1: attribute_dispatch]

03 / HORIZONTAL SCALE AND WHOLE-FRAME CHECK

절반 간격에서 소스 열을 고른다

원본 코드는 Q16 가로 배율을 floor(48×65536/64)로 계산하며 값은 0xc000입니다. 글리프 폭 24·29·34·29는 각각 18·21·25·21로 줄어들며 x 좌표는 96·114·135·160입니다. 높이 48과 y 좌표 64는 유지됩니다. 소스 열은 역배율 간격의 절반에서 시작해 선택하므로 단순히 각 구간의 왼쪽 열을 고르는 계산과 다릅니다. [A1: scale_oracle·evidence]

factor = (48 << 16) // 64
destination_width = (source_width * factor) >> 16
inverse_step = (source_width << 16) // destination_width
source_column = (column * inverse_step + (inverse_step >> 1)) >> 16

원본 축소 실행은 68,969개의 VEX 블록 이벤트 뒤 1을 반환했습니다. 전체 129,536바이트와 양끝 8바이트 보호 구간을 독립 계산과 대조했습니다. 바뀐 바이트 2,464개 중 인덱스 1은 1,297개, 인덱스 2는 1,167개입니다. 이 값은 색상 인덱스이며 실제 RGB 색은 확인하지 않았습니다. [A2: scaled_oracle·check_scaled]
