화면·글꼴 안내

카메라 메뉴는 버튼 입력을 받아 설정값을 바꾸고, 바뀐 화면을 글자·도형·아이콘 픽셀로 다시 그립니다. 이 주제는 Q7의 색공간(Color Space) 선택 화면 하나를 골라 그 전 과정을 펌웨어 원본 코드로 따라간 기록입니다.

핵심 요약

  • 대상은 커스텀 설정 C3 메뉴의 “13. Color Space” 화면입니다. 선택지가 sRGB·AdobeRGB 둘뿐이고 세 기종 모두에 있어, K-3 Mark III 저장소의 UI 이식 연구가 첫 비교 단위로 고른 화면입니다.
  • Q7은 선택지를 옮기는 즉시 설정 RAM에 기록하고, 취소하면 열 때 저장해 둔 값으로 되돌립니다. 이 동작과 화면 갱신 요청, 강조 사각형·선택 아이콘·글자의 픽셀 쓰기를 원본 MIPS 코드를 PC에서 실행해 확인했습니다.
  • 화면 버퍼는 픽셀당 1바이트의 팔레트 번호를 담습니다. 글꼴은 픽셀당 2비트이고, 메뉴 글자는 48×48 크기 요청에 따라 가로로 축소돼 그려집니다.
  • 각 단계는 따로 만든 시험 조건에서 확인했습니다. 버튼에서 화면까지 한 번에 이어진 실행, 실제 팔레트 색, 화면 전송(DMA), LCD 출력은 확인하지 않았습니다.

한눈에 보기

메뉴 화면 하나는 여섯 단계를 거쳐 화면에 나갑니다. 다섯 단계는 원본 코드로 확인했고, 팔레트·DMA·LCD 단계에서 확인된 지식이 끝납니다.

오른쪽 상자를 누르면 해당 문서로 갑니다. 번호 ①~⑤는 아래 읽는 순서의 번호입니다. 단계 3~5는 실제 화면 상태를 이어받지 않고, 앞 단계에서 기록한 인수를 새로 만든 시험 컨텍스트에 다시 넣어 확인했습니다. 단계 사이의 화살표는 펌웨어의 흐름이지, 한 번에 이어서 실행했다는 뜻이 아닙니다.

배경 지식

이 주제의 문서를 읽는 데 필요한 개념만 짧게 정리합니다.

색공간 설정
JPEG에 쓸 색 범위를 sRGB와 AdobeRGB 중에서 고르는 설정입니다. Q7 설명서는 커스텀 설정 C3의 “13. Color Space”로 소개하고 기본값을 sRGB로 적습니다. AdobeRGB를 고르면 파일 이름 앞머리가 IMGP에서 _IMG로 바뀝니다. [설명서 20쪽] [66쪽]
위젯·캔버스·포커스
화면은 글자 라벨, 선택지, 아이콘 같은 부품(위젯)으로 이루어집니다. 캔버스는 위젯을 묶어 키 입력을 나눠 주고, 포커스는 지금 고르고 있는 선택지입니다.
갱신 요청과 큐
상태가 바뀌어도 곧바로 칠하지 않고, UI 서비스의 큐에 “다시 그려라”를 넣습니다. 소비자가 그 메시지를 꺼내 위젯 전체를 다시 쓰고, 위젯은 글자·도형·아이콘 그리기 함수에 요청을 넘깁니다.
그리기 컨텍스트
그릴 버퍼, 글자 크기·색, 그리기 함수 표를 담은 구조체입니다. 화면 버퍼마다 하나가 있고, 버퍼를 교대할 때 “활성 컨텍스트”가 바뀝니다.
글꼴과 글리프
글리프는 글자 하나의 모양 데이터입니다. Q7의 라틴 글꼴은 펌웨어 속 FAT16 영역의 파일이고, 픽셀 하나를 2비트(값 0~3)로 저장합니다.
인덱스 컬러 버퍼와 팔레트
픽셀에 색을 직접 쓰지 않고 팔레트(색표)의 번호를 쓰는 방식입니다. 실제 색은 표시할 때 팔레트에서 찾습니다. Q7 메뉴 버퍼는 픽셀당 1바이트 번호를 씁니다. 팔레트의 실제 RGB 값은 확인하지 못했습니다. [일반 설명: Indexed color]
합성 버퍼와 논리 좌표
시험은 PC 메모리에 만든 버퍼(예: 736×176, 줄 간격 736바이트)에 그렸습니다. 좌표는 그리기 함수가 받은 값입니다. 이 크기와 좌표를 LCD의 화소 수로 바꿔 읽지 않습니다. Q7의 LCD는 공식 사양상 3.0인치, 약 46만 도트입니다. [설명서 78쪽]
정정

이전 판의 문서와 근거 JSON은 메뉴 위치를 “E3”으로 적었습니다. 설명서 20쪽의 인쇄 표기는 C3입니다. PDF에서 글자를 뽑을 때 메뉴 아이콘 “C”가 “E”로 나온 결과이며, 근거 파일 안의 “E3”은 C3 메뉴를 뜻합니다.

색공간 화면의 배치 (개념도)

그리기 요청에 담긴 좌표만으로 화면 요소의 위치를 그려 보면, 제목·선택지 두 줄·안내문·하단 버튼 안내로 이루어진 단순한 목록 화면입니다.

좌표와 줄 구성은 그리기 경로의 갱신 4회에서 나온 값입니다. 강조 영역과 아이콘은 AdobeRGB를 고르면 y = 112로 옮겨 갑니다. 글자 높이 48은 48×48 요청과 안내문 두 줄의 간격(280 → 328)에 맞춰 그렸습니다. 글자의 폭, 실제 색, 화면 바깥 여백은 근거가 없어 그리지 않았습니다.

지금까지 알아낸 것과 아직 모르는 것

화면의 각 부품이 어떤 번호로 버퍼에 쓰이는지까지는 원본 코드로 확인했습니다. 버튼에서 시작하는 연속 실행과 버퍼 이후의 출력은 비어 있습니다.

화면·글꼴 주제 전체의 검증 상태. “확인 + 모델”은 원본 코드를 실행했지만 입력이나 버퍼를 시험이 넣었다는 뜻입니다

읽는 순서

메뉴 동작에서 시작해 요청, 픽셀, 크기·컨텍스트 순으로 읽으면 쉽습니다. 마지막 문서는 앞의 시험들이 깔고 있던 가정(속성과 글자가 같은 컨텍스트를 본다)을 따로 확인합니다.

  • ①

    색공간 화면: 선택·확정·취소

    고르는 동안 설정값은 언제 바뀌는가?

    선택 즉시 RAM에 기록하고, 확정은 유지, 취소는 백업 복원. 6개 사례, 바이트 쓰기 18회.

  • ②

    색공간 화면: 그리기 경로

    다시 그릴 때 무엇을 어디에 그리라고 요청하는가?

    갱신 4회에서 글자 줄 25개, 강조 사각형 20개, 선택 아이콘 픽셀 330바이트.

  • ③

    선택 강조의 픽셀

    강조 사각형은 버퍼에 어떻게 칠해지는가?

    폭과 x에 따라 halfword 루프 또는 GDI. 7개 사례 모두 버퍼 전체 일치.

  • ④

    글꼴 로딩과 글리프 픽셀

    글자 모양은 어디서 와서 어떤 번호로 찍히는가?

    FAT16 속 글꼴 파일, 2비트 코드 → 번호 2·1·3. “sRGB” 버퍼 전체 일치.

  • ⑤

    48×48 요청과 컨텍스트 선택

    글자 크기 요청과 그리기 컨텍스트는 어떻게 연결되는가?

    48×48 → 축소 렌더러, 폭 0.75배. 빈 슬롯이면 이전 컨텍스트에 머묾.

세 기종 UI 이식 연구와의 관계

이 주제는 K-3 Mark III 저장소의 “화면 하나를 다른 기종으로 옮기려면 무엇을 맞춰야 하는가” 연구에서 Q7 몫을 맡습니다.

K-3 Mark III 저장소의 UI 이식 설계는 세 기종이 모두 가진 색공간 화면을 첫 비교 단위로 골랐습니다. 그 설계안은 열기·선택·확정·취소의 네 동작과 확정값·보류값을 뼈대로 잡고, “선택은 보류값만 바꾸고 확정할 때 기록한다”를 제안합니다. K-3 Mark III와 K-3 II는 실제로 보류값을 거치지만, Q7은 즉시 기록·취소 복원이어서 이 제안과 다릅니다.

최종 출력세 기종 모두 미확인—

숫자 ID, 이벤트 번호, 자원 형식, 렌더러는 기종마다 다르므로 같다고 가정하지 않습니다. 화면 코드를 그대로 복사하는 것이 아니라 같은 동작을 대상 기종의 방식으로 다시 만드는 것이 전제입니다. K-3 II 쪽 결과는 K-3 II 저장소의 색공간 메뉴와 표시에 있습니다.
