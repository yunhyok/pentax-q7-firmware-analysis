Pentax Q7 DCP에 저장된 색 처리 요소

상용 프로파일과 matrix-test의 태그·행렬·테이블 구조를 비교했습니다. 실제 렌더링과 펌웨어 동일성은 검증하지 않았습니다.

Q7-DCP-STRUCTURE-27 · 2026-11-13 · 파일 구조 정적 분석

Adobe Standard에는 두 ColorMatrix, 두 ForwardMatrix, 두 HueSatMap과 하나의 LookTable이 있다. 비교한 matrix-test에는 ColorMatrix 두 개만 있다. 두 파일 모두 ProfileToneCurve를 저장하지 않는다.

확인 대상은 로컬 DCP 두 개의 바이트와 K-3 III 저장소의 기존 분석 기록이다. 아래 수치는 재현 결과 JSON에서 가져왔다. Adobe 프로파일 원본, 전체 행렬·곡선·LUT, RAW와 사진은 이 문서에 포함하지 않았다.

각 노드는 색상 이동·채도 배율·명도 배율의 세 FLOAT로 구성된다. 이 표는 전체 노드의 최솟값·최댓값이다. identity 노드는 저장된 세 값이 정확히 (0, 1, 1)인 경우만 센다. 보간 후 픽셀 결과는 계산하지 않았다.

HueSatMap은 각각 2,700노드이고 LookTable은 4,608노드다. 세 테이블 모두 S=0 위치의 명도 배율이 1이며, 채도·명도 배율이 음수인 노드는 없다. LookTable의 명도 배율은 모든 노드에서 1이지만 색상과 채도는 바뀔 수 있다. 이 사실로 전체 렌더링의 밝기가 보존된다고 판단할 수는 없다.

3. ToneCurve와 생략 태그

ProfileToneCurve(50940)가 없으므로 저장 곡선의 0…1 경계, x의 엄격한 증가, y의 비감소, identity 이탈량은 모두 계산 대상 없음(null)으로 기록했다. 검사기는 합성 곡선으로 경계 이탈·중복 x·감소 y·비유한값을 검사한다. 합성 검사 통과를 실제 Q7 곡선 검증으로 표시하지 않았다.

DNG 1.7.1 규격은 저장 ToneCurve의 좌표와 보간 방법을 정의한다. 규격상 LookTableEncoding의 생략 기본값은 linear(0)이며, V=1인 HueSatMap에는 encoding 선택이 적용되지 않는다. BaselineExposureOffset의 기본값은 0 EV, DefaultBlackRender는 Auto다. 이는 규격 해석이며 이번에 Lightroom의 실제 기본 동작을 측정한 결과가 아니다.

두 DCP에는 BaselineExposure(50730)도 없다. RAW의 BaselineExposure, 사용자 노출 조정, 렌더러의 기본 곡선까지 0 또는 identity라고 결론 내릴 근거는 없다.

4. K-3 III 자료와 대조

기존 K-3 III Adobe Standard 메타데이터와 비교했다. HueSatMap의 90 × 30 × 1, LookTable의 36 × 8 × 16 차원과 광원 태그 17·21은 같다. ColorMatrix·ForwardMatrix·HueSatMap 데이터·LookTable 데이터의 payload 해시는 모두 다르다. K-3 III 기록에도 ToneCurve가 없다. 이번에는 K-3 III DCP 원본을 다시 읽지 않았다.

모델 문자열도 구분해야 한다. Adobe 입력은 "PENTAX Q7", matrix-test는 끝에 공백이 있는 "PENTAX Q7 "다. 이 차이가 프로파일 선택 호환성에 미치는 영향은 확인하지 않았다.

  1. 이번 확인DCP 태그·해시·수치 범위. RAW와 렌더러 실행 없음.
  2. 별도 조건As Shot 변화와 프로파일·WB의 결합.
  3. 아직 확인하지 않음최종 픽셀 일치와 펌웨어 Custom Image 일치.

과거 As Shot 기록의 Q7 사례에서는 Lightroom 16.0 표시값이 5100 K / Tint −17에서 4900 K / Tint −7로 바뀌었다. 해당 기록의 strict_profile_only_passed는 false다. 따라서 이를 WB가 고정된 프로파일 단독 비교로 취급하지 않는다. 이번 분석에서 Lightroom을 다시 실행하거나 그 수치를 재측정하지 않았다.

검사기는 K-3 III 저장소의 기존 inspect_adobe_profiles.py를 LF 정규화 SHA-256으로 고정해 재사용한다. 아래 경로 변수에 각 로컬 파일을 지정하고 PowerShell에서 실행한다. 출력 파일은 새 경로여야 한다.

공개 JSON의 연구 관측은 정규화 해시로 전부 검사한다. 재현 출력에는 별도 메타데이터가 추가되므로 공개 파일과 바이트 동일성을 요구하지 않는다. 공개 JSON canonical SHA-256: 23b2e830aa89b48ffc5221bb96fd0651c6839169eb80dc6aea70add6e23d5530. 보고서 빌더는 저장소의 analysis/q7-dcp-structure.json과 analysis/q7-dcp-template.html을 읽는다.

  • Adobe DNG Specification 1.7.1.0: 인쇄 쪽수 32–33(ColorMatrix), 49–53(HueSatMap·ToneCurve·ForwardMatrix), 56–57(LookTable), 62–64(black render·exposure offset·encoding).
  • K-3 III의 공통 DCP 검사기: 본 분석이 고정한 LF SHA-256은 83c9ea9d745a4ac12bba4164ff729aeb8e64bdd3783e8575727251758ee3a7e7이다.
  • 기존 As Shot 근거 JSON: 사용한 파일 해시는 이번 결과의 source_reports에 기록했다.

공개판의 입력과 관측 보존

원본 연구 코드 SHA와 공개 코드의 LF SHA를 _publication에 분리했다. Q7-27의 모든 관측은 그대로 보존하며 원래 관측 객체의 canonical SHA-256을 검사한다. 공개판은 descriptor의 regular-file 여부와 2,000,000바이트 상한을 확인한 뒤 최대 cap+1바이트를 한 번 읽는다. 출처 JSON의 해시 검증과 해석은 그 한 버퍼에서 수행한다.

출력 경로는 입력을 읽기 전과 쓰기 직전에 lexists로 검사해 dangling symlink도 거부한다. x 모드만으로 안전하다고 가정하지 않는다. 두 경로 검사 사이에 파일시스템 상태가 바뀔 가능성을 완전히 제거한 원자적 보장을 주장하지 않는다. -O 실행은 자체 검사의 assert 제거를 막기 위해 거부한다.

source_reports.*.sha256은 출처 파일의 실제 바이트 해시이고 sha256_lf는 CRLF를 LF로 바꾼 뒤의 해시다. 파서와 두 출처 JSON은 LF 해시로 고정한다. profiles.*.file은 사용자가 지정한 파일명이다. 재현 비교는 이 두 환경 의존 항목만 제외하고 태그·수치·역사적 관측을 모두 대조한다. 실제 파일명과 raw 해시는 _reproduction에 남긴다.

기존 inputs_unchanged_after_analysis=true는 Q7-27에서 분석 전후 해시를 확인한 역사적 관측이다. 공개판은 입력을 한 번 캡처하므로 이 사후 검사를 새로 수행했다고 주장하지 않으며 post_analysis_input_reread=false로 기록한다.

git clone https://github.com/yunhyok/pentax-k3iii-firmware-analysis.git k3-reference
 git -C k3-reference checkout 2b50cf4f46a61b077789692b3ccc851d4d8d65b9
python -B tools/check_q7_dcp_structure.py --check-record
python -B -m unittest discover -s tests -p test_q7_dcp_structure.py -v

전체 재현에는 위 커밋의 inspect_adobe_profiles.py, analysis/adobe-profiles.json, analysis/lightroom-as-shot.json이 필요하다. 상용 Adobe DCP는 사용자 설치본을 지정한다. matrix-test도 기록된 SHA와 일치하는 별도 로컬 파일이 필요하며 이번 공개 패키지에 동봉하지 않는다. CI의 공개 기록 검사와 합성 검사는 원본 DCP나 K-3 III 체크아웃 없이 동작한다.

6. 남은 과제

태그 구성만으로 Lightroom의 기본 곡선·노출 처리·출력 색공간이나 카메라의 Custom Image를 복원할 수 없다. 후속 비교에서는 같은 RAW, 고정 WB, 노출·Process Version·출력 프로파일을 명시하고 테이블 추가 여부를 단계별로 나눠야 한다. 끝 공백이 있는 모델 문자열의 호환성도 별도로 확인할 항목이다.

이번 과제는 DCP 구조 분석으로 한정했다. 펌웨어 FC1 비트 의미, HDR task 생성·제출·완료 경로에 대한 새로운 근거는 이 문서에 포함하지 않는다.
