01 / OUTPUT DESCRIPTOR

대체 출력의 타입 필드가 선택 조건이다

path+0x964는 독립된 경로 플래그가 아닙니다. path+0x8fc 대체 출력 디스크립터의 +0x68 필드입니다. 새 경로를 만들 때 이 필드는 0으로 초기화됩니다. 값이 0이면 IpuSubmit은 path+0x28에서 출력 디스크립터를 만들고, 0이 아니면 대체 디스크립터를 복사합니다. [S1: selector·type_0_registry]

HDR 제출 전 설정 함수를 따라가면 필터 설정은 별도의 processor 객체를 수정하고 형식·배율·버퍼 설정은 경로의 앞쪽 필드를 수정합니다. 분석한 호출 순서에서는 대체 출력 디스크립터를 채우는 함수를 호출하지 않습니다. 이 조건에서 format 0x0f01은 type 8 출력 디스크립터로 변환되고 원래 출력 블록 주소는 surface의 첫 워드에 남습니다. [S1: HDR 설정·surface 바인딩]

정상 분기와 대체 분기를 각각 실행하다

제출 분기를 원래 MIPS 명령으로 재실행했습니다. 새 경로에서는 설정한 출력 블록이 선택됐습니다. 비교 사례에서는 실제 PathSetDescriptorsbyId를 호출해 대체 디스크립터를 넣었습니다. 같은 출력 블록 설정을 유지한 상태에서 대체 주소가 선택됐습니다. 메모리 할당·RTOS·하드웨어 초기화 등은 대체 함수로 처리했으며, 전체 카메라 실행을 재현한 것은 아닙니다. [S1: replay] [재현 코드]

이 결과로 이전 보고서의 HDR B → T(B) 연결에서 남겨 둔 IpuSubmit 선택 조건을 좁혔습니다. 새 HDR 경로는 B 내부의 출력 view를 일반 출력 디스크립터로 제출합니다. DMA 완료와 JPEG가 읽은 실제 픽셀은 여전히 검증 범위 밖입니다.

02 / FC CONFIGURATION PRODUCER

HDR 행렬은 FC mode 1에서 그대로 복사된다

FC 객체는 mode 1에서 패스 입력 +0x68의 포인터를 읽습니다. 포인터가 있으면 행렬 계수 9개와 추가 필드 2개를 그대로 복사하고, 없으면 내장 계수를 선택합니다. 이어지는 Export는 11개 halfword를 부호 확장해 32비트 필드로 내보냅니다. 이 경로는 계수를 새로 곱하지 않고 복사하거나 내장값을 선택합니다. [F1: FC 구성·Export]

새 HDR 경로에서 input[1] == 0인 이유

processor 생성자는 디스크립터 슬롯을 비우고 기본값으로 ID 0xf와 0x19만 설치합니다. IpuToneMapRgb는 HDR 보조 설정 ID 0x1f와 로컬 ID 0xa / 0xf를 설치합니다. 보조 설정은 HDR 캐시 생성부와 HdrSetZLightFilter에서 ID 0x1f, version 0xc로 제한됩니다. 분석한 새 경로에는 ID 0x1d가 없습니다. [F1: HDR descriptor 출처·기본값]

PrepareCalculations는 FIPLIB 입력을 0으로 지운 뒤 ID 0x1d가 있을 때만 그 디스크립터의 +0x18에서 입력 +1을 채웁니다. 따라서 이 HDR 경로에서는 입력 +1 = 0입니다. 각 IPU 패스의 준비 함수는 이 값이 1이 아니면 입력 +0x1074를 로컬 패스 입력 +0x68에 연결합니다. 값이 1인 다른 경로는 +0x68을 비우고 +0x6c에 연결하므로 같은 결론을 적용하지 않습니다. [F1: PrepareCalculations·PreparePassInParams]

직접 실행 경로와 COP 작업자 경로의 Analyze·Export 호출 연결을 확인했습니다. 전체 FIPLIB 토폴로지 계산이나 COP 스레드를 동작시킨 것은 아닙니다. 패스별로 이 계수를 저장하는 것과 FC1을 활성화하는 것은 별개입니다.

05 / REPRODUCTION AND LIMITS

정적 연결·제한된 실행·미확정 항목

새 근거 집합은 함수 후보 72개와 원본 명령·데이터 워드 499건입니다. 함수 후보 범위는 다음 sidecar 주소까지이며 공식 함수 크기는 아닙니다. 원본 펌웨어에서 워드, 함수 해시와 전이 정보를 다시 계산해 확인했습니다. [검증 코드]

python -m unittest discover -s tests -v
python tools/verify_report.py --firmware path/to/fwdc603p.bin
# 합성 ELF 생성 절차: deep-report.html#reproduce
python tools/check_submit_choice.py .private/main-expanded.elf --output .private/submit-recheck.json
python tools/check_fiplib_coefficients.py .private/main-expanded.elf --output .private/fc-recheck.json

각 재실행 도구는 입력 ELF의 SHA-256을 검사하고 이미 존재하는 출력 파일을 거부합니다. VEX를 사용했으며 optional Unicorn 엔진은 사용하지 않았습니다. 공개 CI는 원본 펌웨어 없이 메타데이터·기준값·도구 테스트·HTML·링크를 검사합니다. 원본 명령 재실행과 원본 펌웨어 대조는 로컬 검증입니다.

전체 FIPLIB 패스 구성과 스케줄러를 한 번에 실행하지는 않았습니다. 특정 촬영에서의 패스 개수·최종 활성 상태, CBC 실행 완료, DMA와 캐시 동작, JPEG 픽셀의 정확성은 아직 확인하지 못했습니다. 이번 결과는 명시한 분기 조건에서의 소프트웨어 연결과 계수 설정값에 한정합니다.

다음 추적 대상은 패스별 top-control이 FC1 enable·flags를 고르는 조건과 실제 촬영의 패스 수입니다. 최종 픽셀을 확인하려면 하드웨어 실행 또는 확보한 입력·출력 영상과의 대조가 별도로 필요합니다. 원본 BIN·추출 ELF·전체 디컴파일은 공개하지 않습니다.
