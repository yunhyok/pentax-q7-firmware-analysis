# 2026년 11월 2차 검수 기록 — Q7 (v0.4.0)

v0.3.0과 v0.3.1에서 새 보고서가 올라온 뒤, 그 보고서들을 검수하고 사이트 전체의 문장을 다시 다듬었습니다. 이 문서는 그 결과입니다. 1차 기록은 [2026-11-review.md](2026-11-review.md)에 있습니다.

## 무엇을 했나

| 대상 | 한 일 |
|---|---|
| v0.3.x에서 새로 올라온 보고서 7쪽 (NAND 4쪽, DCP 2쪽, `colorspace-clip-report`) | 근거 JSON·검사 스크립트·테스트와 대조한 뒤, 다른 보고서와 같은 형식(요약 → 확인한 범위 → 배경 → 본문 → 한계 → 재현 → 출처)으로 다시 쓰고 그림을 넣었습니다 |
| 안내 문서 `guide-update`, `guide-color`, `guide-ui` | 새 보고서를 지도·표·읽는 순서에 넣었습니다 |
| 기존 보고서 24쪽 | 내용은 그대로 두고 문장만 다듬었습니다 |

모두 34쪽이고 그림은 81개입니다.

새 보고서도 템플릿과 근거 JSON에서 만들어집니다. 이번에 표·그림·합계를 빌더가 JSON에서 만들도록 넓혔고, 템플릿에 적은 숫자는 빌더가 JSON과 같은지 확인합니다.

### 한계

이번에도 원본 펌웨어 없이 검수했습니다. 문서가 공개된 근거 JSON·검사 스크립트와 맞는지 확인했고, 검사 스크립트를 펌웨어에 다시 돌리지는 않았습니다. 펌웨어 없이 도는 검사(`tools/verify_report.py`, 단위 시험 121개)는 통과했습니다.

## 문장 다듬기

한국어 윤문 규칙(humanize-korean)을 적용했습니다. 내용 명사·수치·코드는 그대로 두고 문형만 고치는 방식입니다.

- 연결어미 바로 뒤의 쉼표("~하고, ~")를 뺐습니다. 기존 보고서의 템플릿에서 364곳입니다.
- 문단 128개를 고쳐 썼습니다. 긴 문장을 나누고, "A가 아니라 B입니다" 식 대구와 "~라는 뜻입니다" 식 종결을 직접 서술로 바꿨습니다. 고친 문단마다 태그, 숫자·주소·영문 식별자, 코드, 템플릿 자리표시가 원문과 같은지 기계로 확인한 뒤 반영했습니다.

| 지표 (본문 산문 기준) | 이전 | 이후 |
|---|---|---|
| 연결어미 뒤 쉼표 | 427 | 0 |
| 90자를 넘는 문장 | 53 | 13 |
| "~라는 뜻입니다" 류 종결 | 12 | 0 |
| "A가 아니라 B" 류 대구 | 43 | 20 |
| 설명을 잇는 대시 | 69 | 37 |

남은 대구는 오해를 바로잡는 문장이라 그대로 두었습니다. 남은 대시는 흐름도 칸의 짧은 꼬리표와 표의 빈칸 표시입니다. 개편 전 보고서에 있던 16진수 주소와 해시는 새 보고서에 모두 남아 있습니다.

## 판단이 필요한 항목

**근거가 부족해 쓰지 않았거나 원문대로 둔 것**

- `nand-header-report.html`: 시험용 ID `ec dc`를 해석한 값 `0x100000`(1,048,576)은 512바이트 섹터 수일 가능성이 있습니다(리눅스 커널의 표에서 장치 ID 0xDC는 512MiB). 단위를 보여 주는 근거가 없어 쓰지 않았습니다.
- `nand-header-report.html`: "호출자가 `0x400>>9 = 2`를 계산"한다는 서술은 근거 JSON의 가정을 따랐습니다. 근처 명령을 보면 다른 분기에서는 `0x600>>9 = 3`일 수도 있습니다.
- `reports/nand-boot-read.html`: 요청 번호 9와 상태값 `0xf1`·`0xf2`·`0xf7`은 공개된 FileX에 없습니다. 뜻을 적지 않았습니다.
- `reports/nand-filex.html`: 파티션 표의 칸 배치가 MBR의 둘째 항목과 같아 보이지만 1차 자료로 확인하지 않아 본문에 쓰지 않았습니다.
- `reports/q7-dcp-structure.html`: 시험 프로파일 "PENTAX RAW matrix test 1760"이 어떻게 만들어졌는지 이 저장소에는 설명이 없습니다. K-3 Mark III 저장소의 기록에 따르면 공개 DNG #1760의 태그에서 행렬을 옮겨 만든 파일입니다. 보고서에는 "행렬만 넣어 만든 연구용 시험 파일"로 적었습니다.
- `reports/q7-dcp-interpolation.html`: Adobe DNG SDK 소스의 줄 번호와 F1~F8의 내용은 SDK 묶음이 없어 다시 보지 못했습니다. 원문의 한정 표현을 유지했습니다.
- `colorspace-clip-report.html`: (−9, 0) 배치에서 "글리프 0행의 보이는 열에 칠할 픽셀이 없다"는 문장은 행 시작 값과 쓰기 횟수에서 이끌어 낸 추론입니다.
- `reports/q7-dcp-structure.html`의 As Shot 기록은 Lightroom 16.0에서 얻은 것이고, K-3 Mark III 저장소의 초기 시험은 Lightroom Classic 15.6입니다. 서로 다른 기록입니다.

## 근거 JSON·스크립트에서 발견한 문제

발견한 것이 없습니다. 빌더 한 곳의 검사를 완화했습니다. `tools/build_q7_dcp_interpolation_report.py`가 "자리표시는 정확히 한 번"을 요구하던 것을 "한 번 이상"으로 바꿨습니다. 같은 해시를 본문과 근거 상자 두 곳에 적기 위해서입니다.

## Lightroom 색 프로파일에 대한 판정

이번 릴리스에 카메라 색 프로파일을 넣지 않았습니다. Q7용 후보는 공개 DNG의 태그에서 행렬을 옮겨 적은 시험 프로파일 하나뿐입니다.

- 스튜디오 장면 한 장에서 이 후보가 Adobe Standard보다 카메라 JPEG에 가까웠습니다(픽셀 ΔE00 중앙값 2.211 대 2.803). 그러나 이미지 전체의 위치 맞춤이 기준을 넘겨 일부 영역 39곳만 비교했고, 두 결과 사이에 화이트밸런스 표시값도 달랐습니다(5100 K/−17과 4900 K/−7).
- 시험한 장면과 조명은 하나이고, 표본은 펌웨어 1.00으로 찍은 것입니다(분석 대상은 1.01).
- 후보에는 ForwardMatrix도 색상·채도 표도 없습니다. 펌웨어에서 찾은 색 행렬을 프로파일로 옮기는 방법은 아직 없습니다.

수치의 출처와 세 기종의 비교는 K-3 Mark III 저장소의 [Lightroom 색 프로파일 안내](https://yunhyok.github.io/pentax-k3iii-firmware-analysis/analysis/guide-lightroom.html)에 있습니다.

## 외부 자료로 확인한 사실 (요약)

- DNG 규격 1.7.1.0: ColorMatrix(32쪽), HueSatMap의 저장 순서(49~50쪽), ProfileToneCurve(51쪽), ForwardMatrix(52쪽), LookTable의 적용 위치(56~57쪽), 기본값들(62~64쪽). 보고서의 서술과 맞았습니다. CalibrationIlluminant 17은 표준광 A, 21은 D65입니다.
- FileX 공개 소스: 드라이버 요청 4는 초기화, 5는 부트 섹터 읽기, 상태 0x90은 입출력 오류. `fx_media_open`의 인수는 6개(오류 검사 빌드에서는 7개).
- 리눅스 커널의 NAND 표: 제조사 ID(0x98 Toshiba, 0xEC Samsung, 0xAD Hynix), 장치 ID(0xDC는 512MiB, 0xF1은 128MiB).
- ONFI 규격 사이트는 열리지 않아 인용하지 않고 커널 자료로 대신했습니다.
