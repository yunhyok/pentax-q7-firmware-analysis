# v0.3.0 — Q7 부트·글자 클립·DCP 연구

펌웨어 1.01의 NAND·FileX 경로와 색공간 글자 전송을 조사한 연구 릴리스입니다. 원본 코드를 실행한 구간, 시험에서 준비한 상태, 아직 응답을 확인하지 못한 지점을 보고서에 표시했습니다.

## 재구축과 부팅

- NAND 식별값과 부트 헤더 값의 사용처, 별도로 공급한 부트 읽기 요청을 확인했습니다. 컨텍스트 등록과 별도 매체 발견을 구분했고, AppFb의 FileX 열기에서 아직 해소하지 못한 NAND 상태 응답까지 추적했습니다. 물리 NAND의 보존·쓰기·부팅과 복구는 검증하지 못했습니다. [NAND 부트 헤더](https://yunhyok.github.io/pentax-q7-firmware-analysis/nand-header-report.html) · [부트 읽기](https://yunhyok.github.io/pentax-q7-firmware-analysis/reports/nand-boot-read.html) · [FileX와 NAND 응답](https://yunhyok.github.io/pentax-q7-firmware-analysis/reports/nand-filex.html)

## 색과 AF

- 고정된 Adobe Standard와 연구용 matrix-test DCP의 구조·태그·행렬 차이를 비교했습니다. Adobe DCP에는 2,700노드 HueSat 표 두 개와 4,608노드 Look 표가 있으며, ToneCurve 태그 부재를 항등 렌더로 해석하지 않습니다. Adobe 원본은 별도 입력이고 이 구조 비교는 새 Lightroom 출력이나 카메라 색 재현을 검증하지 않습니다. [DCP 구조 비교](https://yunhyok.github.io/pentax-q7-firmware-analysis/reports/q7-dcp-structure.html)

- 이전에 확인한 FC1·HDR 경로와 Lightroom Bright 스튜디오 비교는 서로 다른 근거입니다. 스튜디오의 전역 정합은 기준을 충족하지 않아 통과한 국소 영역만 사용했습니다. Q7 카메라 렌더와 정확히 맞는 프로파일은 아직 확보하지 못했습니다. [HDR 작업 경로](https://yunhyok.github.io/pentax-q7-firmware-analysis/hdr-task-report.html) · [Bright 스튜디오 비교](https://yunhyok.github.io/pentax-k3iii-firmware-analysis/analysis/lightroom-studio-baseline.html)
- 기존 AF 분석은 명령·전송 응답과 별도의 완료 판정 경로를 구분합니다. 실제 렌즈 이동과 광학 초점은 검증하지 못했습니다. [AF 명령과 완료 판정](https://yunhyok.github.io/pentax-q7-firmware-analysis/af-completion-report.html)

## UI와 글꼴

- 18×48 단일 글리프를 합성 8비트 인덱스 표면에 그리는 일곱 조건을 비교했습니다. 좌상단 원점 (−9,−12)에서 행 시작 주소 검사가 먼저 적용돼, 단순 사각형 교차라면 그릴 첫 화면 행의 픽셀 8개도 건너뛰었습니다. 이 결과는 해당 글리프와 위치에 한정됩니다. 실제 메뉴 좌표·팔레트·LCD 출력과 K-3 III 화면 이식은 남아 있습니다. [글자 가장자리 처리](https://yunhyok.github.io/pentax-q7-firmware-analysis/colorspace-clip-report.html)
