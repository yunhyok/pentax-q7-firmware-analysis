# v0.2.0 — 문서 전면 개편과 내용 검수

연구 결과는 그대로 두고, 문서를 읽기 쉽게 다시 쓰고 내용을 검수한 릴리스입니다. 새로운 분석 결과는 없습니다.

문서: https://yunhyok.github.io/pentax-q7-firmware-analysis/

## 문서가 어떻게 바뀌었나

- **주제별로 묶었습니다.** 조사한 순서대로 나열되어 있던 보고서 21쪽을 5개 주제(시작하기, 업데이트와 재패킹, 색 처리와 HDR, AF와 렌즈 제어, 화면과 글꼴)로 나눴습니다. 모든 페이지 위쪽에 같은 탐색 줄이 있고, 아래쪽에 같은 주제의 이전·다음 문서가 있습니다.
- **주제마다 안내 문서를 새로 썼습니다.** 업데이트, 색 처리, AF, 화면 안내 문서가 전체 흐름을 그림 한 장으로 보여 주고 세부 보고서를 읽는 순서를 알려 줍니다.
- **첫 화면을 새로 만들었습니다.** 연구의 목표와 현재 위치, 펌웨어 파일의 구성, 문서 지도를 담았습니다. 예전 첫 화면에 있던 파일 구조 분석은 `structure-report.html`로 옮겼습니다.
- **모든 보고서를 같은 순서로 다시 썼습니다.** 요약 → 확인한 범위 → 배경 설명 → 본문 → 한계 → 재현 방법 → 출처. 주소·해시·사례 표 같은 세부 근거는 접어 두었습니다.
- **그림을 넣었습니다.** 흐름도, 메모리 배치, 상태 전이, 자료 구조 그림 68개를 본문에 넣었습니다. 모두 문서 안에 들어 있는 SVG라서 오프라인에서도 보입니다. 첫 화면에는 카메라 사진을 실었습니다(Wikimedia Commons, 출처는 `assets/photos/CREDITS.md`).
- **근거의 수준을 표시했습니다.** 결과마다 확인(원본 코드를 PC에서 실행), 정적 분석, 모델, 미확인 가운데 어느 것인지 같은 색과 이름으로 표시합니다.
- **용어집을 만들었습니다.** 세 기종 문서에 나오는 용어를 `glossary.html` 한 곳에서 설명합니다.
- **배경 설명과 외부 자료를 보탰습니다.** 리코의 사용설명서와 제품 자료, ThreadX·FileX 공개 소스, MIPS 문서, ITU-R BT.601 등 1차 자료를 확인하고 링크했습니다.

기존 보고서의 파일 이름과 주소는 바뀌지 않았습니다. 새 문서는 6쪽입니다(안내 문서 4쪽, 파일 구조, 용어집).

## 내용 검수에서 고친 것

수치·주소·해시를 근거 JSON과 검사 스크립트에 대조하고, 외부 사실을 1차 자료로 확인했습니다. 수치·주소·해시에서는 오류를 찾지 못했습니다. 고친 것은 다음과 같습니다.

- 색공간 메뉴의 위치를 "E3"으로 적은 곳을 "커스텀 설정 C3"으로 고쳤습니다. PDF에서 글자를 뽑을 때 생긴 오류였습니다. 사용설명서 링크의 쪽 번호도 고쳤습니다.
- 뒤 보고서가 이미 해결했거나 좁힌 서술이 앞 보고서에 "미확인"으로 남아 있던 곳을 현재 상태로 바꿨습니다. `deep-report.html`의 AF 수신자, JPEG 압축 경로, 색 행렬 경로와 `pixel-report.html`의 HDR 계수 유지 여부가 그렇습니다.
- 근거 꼬리표 두 개의 키 이름을 실제 JSON의 키 이름으로 고쳤습니다.
- 잘못 읽히기 쉬운 표현 두 곳을 고쳤습니다. `loader-hash-report.html`의 그림에서 "마지막 1,536바이트"는 버퍼 맨 앞 1,536바이트를 뜻하고, `recompiled-numeric-report.html`의 K-3 비교 문단은 첫 시도가 거부된 뒤 다른 방법으로 들어갔다는 순서가 빠져 있었습니다.

전체 목록, 판단이 필요해 남겨 둔 항목, 근거 JSON에서 발견한 문제는 [`docs/audit/2026-11-review.md`](https://github.com/yunhyok/pentax-q7-firmware-analysis/blob/main/docs/audit/2026-11-review.md)에 있습니다.

## 알아 둘 점

- 검수는 원본 펌웨어 없이 했습니다. 문서가 공개된 근거 JSON·검사 스크립트와 맞는지 확인했고, 검사 스크립트를 펌웨어에 다시 돌리지는 않았습니다.
- 근거 JSON과 검사 스크립트의 분석 내용은 고치지 않았습니다. `analysis/hq-status.json`에 적힌 보고서 HTML의 해시는 개편 전 파일의 값이며, 그 사실을 같은 파일에 적어 두었습니다.
- 이번 개편에서 배경 설명으로 넣은 외부 규격과의 비교(예: FC1 계수와 BT.601 계수)는 본문에 해석이라고 적었습니다. 목록은 검수 기록에 있습니다.
- 이 저장소에는 여전히 원본 펌웨어, 제조사 코드, 카메라에 넣을 수 있는 펌웨어가 없습니다. 모든 분석은 PC에서 했습니다.

## 도구

- 보고서의 글은 이제 `analysis/*-template.html`에 있습니다. 예전의 `*-copy.json`, `*-editorial.json`은 없앴습니다. 표와 합계는 빌더(`tools/build_*_report.py`)가 근거 JSON에서 만들고, 템플릿에 적은 숫자가 근거와 다르면 생성이 멈춥니다.
- `tools/build_all.py`: 탐색 줄을 갱신하고 모든 보고서를 다시 만듭니다.
- `tools/verify_report.py`: 보고서를 다시 만들어 저장된 파일과 바이트 단위로 비교하고, 손으로 쓴 페이지의 구조와 링크, 탐색 줄도 검사합니다.
- `assets/site.css`: 세 저장소가 함께 쓰는 스타일시트. 밝은 화면과 어두운 화면, 인쇄, 좁은 화면을 지원합니다. 예전 `assets/report.css`와 `assets/deep.css`는 지웠습니다.
- `site-map.json`, `tools/site_chrome.py`: 문서 지도와, 그것으로 모든 페이지의 탐색 줄을 채우는 도구.
- `.github/workflows/release.yml`: `docs/releases/<버전>.md`가 main에 들어오면 검사를 돌린 뒤 릴리스를 만듭니다.

## 내려받기

`pentax-q7-firmware-analysis-v0.2.0.zip`에 저장소 전체가 들어 있습니다. 압축을 풀고 `index.html`을 브라우저로 열면 됩니다. `SHA256SUMS.txt`로 파일을 확인할 수 있습니다.
