01 / PROGRAM-SOURCE ATTRIBUTION

차이를 만든 쓰기를 원본 코드에 연결한다

앞선 합성 NAND 조건에서 관측한 3,242회는 VEX 메모리 쓰기 이벤트 수입니다. SWL/SWR가 바이트 쓰기로 나뉘므로 MIPS 저장 명령 실행 횟수와는 집계 단위가 다릅니다. 헤더·섹션 표·파티션 필드를 바꾸는 170개 이벤트만 적용해도 최종 버퍼와 같은 해시가 나왔습니다. 뒤의 3,072개 이벤트는 첫 1,536바이트를 복사하며 이 사례에서는 값을 바꾸지 않았습니다. [H1: header_replay.trace]

헤더 +0x214는 0x1367b에서 0x13600으로 바뀌고 +0x310과 +0x314에는 설치 헤더에서 받은 640·384가 복사됩니다. +0x3a8과 +0x3ac에는 합성 영역 정보 1·0이 기록됩니다. 섹션 0의 36바이트와 섹션 1~6의 216바이트도 출력 헤더로 복사됩니다. 모든 차이는 첫 1,536바이트 안에 있습니다. [H2: trace]

+0x230과 설치 헤더 [0x318, 0x398)의 128바이트도 복사되지만 이번 입력에서는 기존 값과 같습니다. 변경 범위와 쓰기 명령별 이벤트 수·해시는 H1에 기록했습니다. 첫 op 5의 호출 명령과 delay slot을 실행한 뒤 FCU 진입점 0x8008249c에서 멈췄으며 op 5 처리는 실행하지 않았습니다.

02 / PARTITION FIELD WRITES

조건과 숫자 필드를 먼저 확인한다

UpdatePartitionInMBRTable은 섹션 +0xc가 999이거나 +4의 span이 0이면 쓰기를 생략합니다. 나머지 시험 사례에서는 ID당 16바이트 간격으로 +8에 시작값, +12에 길이, +4에 1을 씁니다. ID 0일 때만 +0에 0x80을 직접 씁니다. 실제 합성 헤더의 네 항목 모두 +0이 0x80인 것은 나머지 항목의 기존 값도 같았기 때문입니다. 이 필드만으로 파일시스템 종류나 실제 NAND 배치를 확정하지 않았습니다. [H1: findings.partition·mbr_cases]

03 / NATIVE DIGEST AND WORKER

계산 결과를 실제 완료 메시지로 넘긴다

원본 md5_init·md5_append·md5_finish와 내부 압축 함수를 대체하지 않고 실행했습니다. 길이 0·1·3·55·56·63·64·65·119·120·127·128·129바이트를 한 번에 넣거나 나누어 넣은 26개 사례에서 기준값과 일치했습니다. 입력·컨텍스트·출력 주변의 보호 바이트와 종료 전 비트 수도 확인했습니다. [H1: hash_replay.primitive_cases]

MD5("")    = d41d8cd98f00b204e9800998ecf8427e
MD5("abc") = 900150983cd24fb0d6963f7d28e17f72

알고리즘과 두 벡터는 RFC 1321과 대조했습니다. 펌웨어의 정책은 원본 명령과 실행 결과로 판단했습니다.

BurnHashManager는 입력 큐에서 명령 0으로 초기화하고 1로 데이터를 추가하며 2로 최종 다이제스트를 비교합니다. 같으면 결과 큐에 3, 다르면 4를 보냅니다. 명령 5는 결과 큐로 전달한 뒤 종료합니다. 추가할 포인터의 0x40000000 비트가 있으면 0x80000000을 OR하고 없으면 0xdfffffff로 AND합니다. 두 포인터 분기도 합성 주소에서 실행했으며 실제 캐시 효과를 검증한 것은 아닙니다. [H1: worker_cases]

초기화·추가 래퍼는 큐 API의 반환 상태와 무관하게 1을 반환합니다. 완료 래퍼는 전달받은 첫 워드가 3인지 검사합니다. 상태값을 달리 준 9개 합성 사례에서 이 계약을 확인했습니다. 큐가 정상 전달된다는 조건과 해시 계산의 성공을 구분해야 하며 이 결과만으로 실제 큐 오류의 영향이나 발생 가능성을 판단하지 않았습니다. [H3: wrappers]

04 / CARD RETRY WITH NATIVE HASH RESULTS

성공 값 주입을 실제 해시 비교로 대체한다

해시 사용 플래그를 1로 둔 카드 콜백 7개 사례에서 원본 래퍼와 작업자까지 연결했습니다. 80바이트 전체를 읽는 조건에서 앞 64바이트를 해시하고 뒤 16바이트와 비교합니다. 작업자가 보낸 3은 성공으로 이어지고 4는 되감기와 재시도로 이어집니다. 재시도 성공, 두 번 불일치, 읽기 오류와 되감기 오류를 포함해 원본 코드의 해시 작업 9건을 관측했습니다. 작업자에는 콜백 메모리 복사본과 실제 메시지를 넘기고 순서대로 실행했습니다. [H4: replay]

05 / K-3 MARK III COMPARISON

같은 항목을 기종별 근거로 판단한다

06 / REPRODUCTION AND LIMITS

검증한 경계와 남은 경계를 함께 기록한다

설치 헤더와 NAND 형상은 합성값이며 첫 기록 요청은 FCU 진입에서 op 5 처리 전에 멈췄습니다. 해시 콜백 검사는 전체 길이의 읽기만 다뤘고 짧은 읽기나 실제 RTOS 스케줄링은 검증하지 않았습니다. 전체 BurnNand 기록·복구 루프, 하드웨어 캐시, 카메라의 패키지 수용·기록·부팅도 미검증입니다.

헤더·해시 word 101개와 함수 범위 14개, 카드 연결 word 71개와 함수 범위 10개를 원본과 대조했습니다. MD5 26+8+9와 카드 7사례는 작업자·조정자의 별도 실행 결과가 일치했습니다. MBR 7사례도 독립 재실행했고 전체 헤더 추적은 조정자가 수행했습니다. [H1] · [H4]
