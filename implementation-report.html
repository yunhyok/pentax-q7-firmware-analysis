01 / ROUND-TRIP AND CONTROLLED EDIT

원본 재생성과 한 명령 변경을 각각 검증했다

원본의 압축 블록 448개를 해석한 뒤 같은 토큰으로 다시 직렬화했습니다. 전체 파일의 SHA-256은 원본과 일치했습니다. 변경 실험에서는 GetFirmwareReleaseVersion의 반환값을 0에서 1로 바꾸는 명령 하나를 교체했습니다. 기존 블록 공간 안에서 영향을 받은 토큰을 보정하고 체크섬을 다시 계산한 뒤 모든 세그먼트를 재복원해 요청한 바이트와 대조했습니다. [R1: roundtrip·patched]

도구는 원본 토큰 중 변경된 이력과 충돌하는 복사 토큰을 해당 블록의 리터럴 코드로 바꿉니다. 다음 블록이 앞 블록을 참조하는 경우도 검사합니다. 필요한 리터럴이 없거나 기존 공간을 넘으면 오류로 중단합니다. 코드 삽입·삭제, 일반 압축기와 재배치는 아직 지원하지 않습니다. [리패커] · [경계 테스트]

반환값 변경은 재생성 경로를 확인하기 위한 통제된 실험입니다. AF·UI 기능을 변경한 펌웨어가 아니며, 변경 이미지는 배포하지 않습니다.

02 / APPLICATION GATE AND BURN LOADER

앱 파일 검사와 실제 기록 경로를 구분한다

애플리케이션의 UpdateFW_IsCorrectUpdateFirmware는 마지막 32바이트에서 세 식별자와 체크섬을 검사합니다. 체크섬은 마지막 32바이트를 제외한 바이트 합의 하위 32비트입니다. 파일 시스템과 메모리 할당은 모델로 대체했습니다. 원본 명령 재실행은 13가지 사례에서 모두 통과했습니다. 이 검사 결과로 이후 기록 단계의 모든 조건을 충족했는지까지 판단할 수는 없습니다. [R1: application_gate]

footer = file[-32:]
footer[0:8], [8:16], [16:24] = ORION / KB538 / 77690
LE32(footer+24) == sum(file[:-32]) mod 2^32
footer[28:32] = 01 01 17 0a

식별자 3종 불일치, 체크섬 불일치, 본문 변경 후 체크섬 재계산 여부, 파일 읽기·할당 실패를 검사했습니다. 마지막 버전 4바이트를 바꾼 합성 파일도 이 함수에서는 통과했습니다. 이는 이 함수의 결과이며, 전체 업데이트 정책에서 버전 검사가 없다는 뜻은 아닙니다. [13사례 원본 명령 재실행]

별도 E01 부트로더는 파일 오프셋 0x100000의 burn header를 읽습니다. 제공된 이미지의 kind는 3이며 BurnGetHandle은 BurnNand를 선택합니다. 헤더의 선택적 MD5 worker 플래그는 0입니다. 플래그가 켜진 경로에서 MD5 비교 코드도 확인했습니다. 이 결과로 다른 무결성 검사나 저장 장치 조건이 없다고 판단할 수는 없습니다. [R1: boot_loader]

03 / AUTOFOCUS FOUNDATIONS

피크 계산, 렌즈 정책과 명령 전달을 나누어 조사한다

AF 변경은 향후 작업입니다. 이번 목표는 기본 구조를 충분히 파악하는 것입니다. 피크 추정 함수는 위치의 정수 배열과 대비의 실수 배열을 받아 위치 추정값을 반환합니다. CalcFocus 호출 지점을 분리하면 워블 AF의 별도 호출을 구분할 수 있지만 원본 코드의 전역 작업 공간과 호출 규약을 함께 보존해야 합니다. 렌즈별 보정과 제한 정책, 명령 전달 및 완료 조건은 피크 계산과 구분해 추적합니다. [P1: af]

LensDriveControl은 모드·방향 등 u8 필드, u16 값과 u32 위치차를 공유 구조에 쓴 뒤 초기화된 콜백을 통지합니다. 하위 제한 모드가 켜진 조건에서는 큐 제출을 막고 status 8을 반환하며, 관측한 대기 시간 초과 경로에는 status 6이 있습니다. RAM에서 확인한 인자는 실제 통신선에서 캡처한 프레임이 아닙니다. [기존 렌즈 경로] · [P1: lens_abi]

공식 자료는 01·02 Q 렌즈의 렌즈 내부 AF 모터를 설명하고, Q7 FAQ는 Adapter Q의 K-mount 렌즈를 수동 초점으로 구분합니다. Q7의 알고리즘 연구에 K-mount 바디 구동계를 그대로 대입하지 않습니다. [Q 렌즈 모터] · [Q7 지원 조합]

04 / Q7 RESOURCE AND DISPLAY ABI

아이콘 ID, 저장 폭과 그리기 규칙을 확인했다

Q7의 LCD 아이콘 경로는 팔레트 인덱스 한 바이트를 화면 버퍼에 기록합니다. 투명 인덱스 0과 재색칠 규칙을 포함해 원본 아이콘 그리기 두 사례를 검증했습니다. K-3 Mark III의 메뉴 구성을 Q7에서 재현하려면 Q7의 물리 입력, 설정 ID, 문자열·폰트와 화면 구성을 사용해야 합니다. 명령어 집합과 리소스 형식이 달라 기존 바이너리의 직접 이식은 확인되지 않았습니다. [P1: ui]

BootStill의 테이블 수로 확인한 범위는 RLE bank ID 1…248과 Zoran bank ID 1001…1546입니다. 디스패치 함수만으로 두 범위 사이의 잘못된 ID가 안전하다고 볼 수 없습니다. 아이콘의 논리 폭과 압축 해제 데이터 폭도 다릅니다.

문자열과 폰트는 별도 자원 경로입니다. 기존 아이콘만 치환해 메뉴 언어와 글꼴까지 이식했다고 볼 수 없습니다. 다음 단계에서는 자원 길이·캐시·팔레트 경계를 유지한 새 자원 실험과 메뉴의 포커스·확인·취소 상태 전이를 분리해 검증합니다.

06 / REPRODUCTION AND REMAINING WORK

파일·명령 검증을 실기 성공으로 확대하지 않는다

이번 검증은 파일 구조와 원본 MIPS 명령, 합성 메모리에 한정됩니다. 카메라 플래시 기록, 부팅, 센서 픽셀, 실제 렌즈 구동과 LCD 출력은 실행하지 않았습니다. 원본 펌웨어와 추출 자원, 변경 이미지는 비공개 분석 폴더에 보관합니다. 공개 저장소에는 도구와 주소·해시·검증 결과만 올립니다.

  • 재생성: 전체 448블록 재복원, 원본 byte-identical 및 변경 코드 0→1 실행.
  • 앱 검사: 13사례; file I/O·allocator·로그를 모델링하고 원본 비교·합산 코드를 실행.
  • 부트 헤더: 5사례; allocator·로그만 대체하고 플래시 콜백 호출 전 중단.
  • AF·UI: 6 AF + 6 geometry + 2 draw 사례; draw buffer getter 한 곳을 대체. 실제 카메라·모터·LCD를 실행하지 않음.
