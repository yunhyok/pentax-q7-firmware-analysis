01 / FILE INPUT CALLBACK

일반 입력은 두 번 읽어 비교한다

{{card}} [L1: replay.card_cases]

{{card_graph}}

콜백 테이블은 E01의 0x800a74dc이며 읽기 함수는 0x80019014, 준비 함수는 0x80019390입니다. 준비 함수는 1을 반환합니다. 읽기 실패, 되감기 실패, 길이 불일치, 바이트 불일치와 재시도를 14개 사례로 확인했습니다. [원본 재실행 도구]

두 번 읽은 실제 길이가 모두 8바이트 또는 0바이트이고 FileX 결과가 성공이면, 이 콜백만은 1을 반환했습니다. 이는 짧은 업데이트가 전체 검사를 통과한다는 증거가 아닙니다. 해시 분기의 계산 결과와 파일 I/O는 모델 입력입니다.

03 / LENS INFORMATION TO AF POLICY

AF 지원은 통신 상태와 연산 비트맵을 함께 본다

{{lens}} [A1: discovery]

{{lens_graph}} 
LLC startup 0x80111448:
  (0, 1, 0, 1)     → 8-byte function-group bitmap
  (0, 1, group, 0) → 32-byte operation bitmap
  LSB-first expansion → operation_flags[u8(group)*256 + u8(operation)]
ExGetAfEnable 0x80114b08:
  (communication_state & 0x08) != 0 AND operation_flags[2*256 + 4] != 0

명령 전송 함수는 map-read-OK가 정확히 1일 때 연산 비트맵을 검사하고, 허용값이 0이면 하위 전송 전에 7을 반환합니다. 이 전송 함수는 AF 지원 getter의 통신 상태 0x08 검사를 반복하지 않습니다. 두 검사를 같은 조건으로 합치지 않았습니다. [A1: transport_admission]
