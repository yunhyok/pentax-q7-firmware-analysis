02 / FC CONFIGURATION PRODUCER

HDR 행렬은 FC mode 1에서 그대로 복사된다

{{producer}} [F1: FC 구성·Export]

{{producer_graph}}

새 HDR 경로에서 input[1] == 0인 이유

processor 생성자는 디스크립터 슬롯을 비우고 기본값으로 ID 0xf와 0x19만 설치합니다. IpuToneMapRgb는 HDR 보조 설정 ID 0x1f와 로컬 ID 0xa / 0xf를 설치합니다. 보조 설정은 HDR 캐시 생성부와 HdrSetZLightFilter에서 ID 0x1f, version 0xc로 제한됩니다. 분석한 새 경로에는 ID 0x1d가 없습니다. [F1: HDR descriptor 출처·기본값]

PrepareCalculations는 FIPLIB 입력을 0으로 지운 뒤 ID 0x1d가 있을 때만 그 디스크립터의 +0x18에서 입력 +1을 채웁니다. 따라서 이 HDR 경로에서는 입력 +1 = 0입니다. 각 IPU 패스의 준비 함수는 이 값이 1이 아니면 입력 +0x1074를 로컬 패스 입력 +0x68에 연결합니다. 값이 1인 다른 경로는 +0x68을 비우고 +0x6c에 연결하므로 같은 결론을 적용하지 않습니다. [F1: PrepareCalculations·PreparePassInParams]

객체 기준을 구분한 데이터 연결
단계코드필드 관계
상위 값 수집PrepareCalculations 0x80349814ID 0xf v0xc의 11 halfwords → FIPLIB input+0x1074..0x1088
FC 객체 생성IPU pass constructor 0x80176ec0pass+0x118의 FC 블록을 mode 1로 생성
패스 입력기본 클래스와 IPU 파생 클래스의 준비 함수local = pass+0x88c; local+0x68 = pass+0x8f4
계수 설정call 0x80178400 → ConfigIntRegs 0x8017ab94mode 1 + 포인터 존재 → 11 halfwords를 FC block+0x10..0x24로 복사

직접 실행 경로와 COP 작업자 경로의 Analyze·Export 호출 연결을 확인했습니다. 전체 FIPLIB 토폴로지 계산이나 COP 스레드를 동작시킨 것은 아닙니다. 패스별로 이 계수를 저장하는 것과 FC1을 활성화하는 것은 별개입니다.

03 / VALUES AND GATES

확인한 최종 값은 계수 9개와 보조값 2개다

 612   1202    233
−346   −678   1024
1024   −857   −167

companion values: 2048, 2048

이 11개 값은 HDR의 상위 디스크립터에서 FIPLIB 입력·FC 블록·출력 payload를 거쳐 FC1 객체까지 유지됩니다. FC1 writer는 계수와 보조값을 부호 확장해 0xb60000c0..0xb60000e8에 기록합니다. FIPLIB가 FC1 값을 덮어쓸 수 있다는 이전 분석은 그대로 유효하며, 여기서 검증한 FC mode 1 계수 경로에서는 그 덮어쓰기 값이 같다는 뜻입니다. 패스별 토폴로지·활성화 값은 후속 보고서에서 구분하며, 이 여섯 합성 사례만으로 전체 HDR 패스의 동작을 검증했다고 보지는 않습니다. [F1] [N1]

계수 이외의 제어값은 따로 판단해야 합니다
대상확인한 식·조건남은 범위
FC1 제어 워드mode 1에서는 payload+0x12c = local pass input[0x28] & 1; writer 주소 0xb60000fc실제 촬영의 모든 패스에서 이 비트를 고정하지 않음
FC1 활성화payload+0x44 바이트 == 0일 때 enable. 이 값은 general block+0x3f ← pass+0x8b0의 별도 top-control 값모든 패스에서 FC1이 활성이라는 결론은 아님
갱신·제출wrapper 존재, dirty/force gate, 패스 선택 범위, UID·writer dirty 조건조건별 상세는 이전 패스 보고서. 특정 촬영에서 모두 충족됐다는 실측은 없음

05 / REPRODUCTION AND LIMITS

정적 연결·제한된 실행·미확정 항목

새 근거 집합은 함수 후보 {{function_count}}개와 원본 명령·데이터 워드 {{word_count}}건입니다. 함수 후보 범위는 다음 sidecar 주소까지이며 공식 함수 크기는 아닙니다. 원본 펌웨어에서 워드, 함수 해시와 전이 정보를 다시 계산해 확인했습니다. [검증 코드]

python -m unittest discover -s tests -v
python tools/verify_report.py --firmware path/to/fwdc603p.bin
# 합성 ELF 생성 절차: deep-report.html#reproduce
python tools/check_submit_choice.py .private/main-expanded.elf --output .private/submit-recheck.json
python tools/check_fiplib_coefficients.py .private/main-expanded.elf --output .private/fc-recheck.json

각 재실행 도구는 입력 ELF의 SHA-256을 검사하고 이미 존재하는 출력 파일을 거부합니다. VEX를 사용했으며 optional Unicorn 엔진은 사용하지 않았습니다. 공개 CI는 원본 펌웨어 없이 메타데이터·기준값·도구 테스트·HTML·링크를 검사합니다. 원본 명령 재실행과 원본 펌웨어 대조는 로컬 검증입니다.
