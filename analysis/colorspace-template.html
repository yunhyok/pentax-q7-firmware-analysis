화면과 글꼴 · ① 메뉴 동작: 고르고, 확정하고, 취소하기

색공간 화면에서 고르기·확정·취소가 값을 바꾸는 방식

메뉴에서 sRGB와 AdobeRGB 중 하나를 고를 때 카메라가 설정값을 언제 기록하는지 알아봤습니다. 다른 기종으로 화면을 옮길 때 가장 먼저 맞춰야 하는 동작이기 때문입니다.

핵심 요약

  • Q7의 색공간 화면은 선택지를 옮기는 즉시 설정 RAM에 값을 씁니다. 확정은 그 값을 그대로 두고, 취소는 화면을 열 때 저장해 둔 백업값을 다시 씁니다.
  • 원본 MIPS 코드를 PC 에뮬레이터에서 실행해 {{case_count}}개 사례(양방향의 확정·취소, 두 값의 같은 값 확정)를 열기부터 다시 열기까지 따라갔습니다. 설정 함수 호출 {{setter_calls}}회와 실제 바이트 쓰기 {{stores}}회가 일치했습니다.
  • K-3 Mark III 저장소의 공통 UI 설계안은 “고르는 동안은 보류값만 바꾸고 확정할 때 한 번 쓴다”를 제안합니다. Q7의 원본 동작은 이와 다릅니다.
  • 물리 버튼에서 이벤트가 나오는 과정, 설정의 영구 저장, 실제 화면 출력은 확인하지 않았습니다.

배경: 색공간 메뉴와 이 문서의 위치

색공간은 카메라가 JPEG를 만들 때 쓸 색 범위를 sRGB와 AdobeRGB 중에서 고르는 설정입니다. Q7 공식 사용설명서는 이 항목을 커스텀 설정 C3 메뉴의 “13. Color Space”로 소개하고 기본값을 sRGB로 적습니다. AdobeRGB를 고르면 파일 이름 앞머리가 IMGP에서 _IMG로 바뀝니다. [설명서 20쪽] [설명서 66쪽]

정정

이전 판과 근거 JSON은 메뉴 위치를 “E3”으로 적었습니다. 설명서 20쪽의 인쇄 표기는 C3입니다. PDF에서 글자를 뽑으면 메뉴 아이콘 “C”가 “E”로 나옵니다. 원본 함수 이름 CustomMenu3Mode_…도 커스텀 메뉴 3을 가리킵니다. 근거 파일 안의 “E3”은 이 C3 메뉴를 뜻합니다.

이 문서는 재생 중 RAW 현상 화면의 색공간이 아니라 촬영 설정 화면을 다룹니다. 이 화면 하나를 메뉴 동작에서 픽셀까지 다섯 문서로 따라갔고, 이 문서는 첫 단계입니다.

  1. ① 선택·확정·취소이 문서
  2. ② 그리기 요청그리기 경로
  3. ③ 강조 픽셀선택 강조의 픽셀
  4. ④ 글자 픽셀글꼴 로딩과 글리프 픽셀
  5. ⑤ 글자 크기·컨텍스트48×48 요청과 컨텍스트 선택
  6. 팔레트·LCD미확인

전체 지도는 화면·글꼴 안내에 있습니다. 이 문서에서 쓰는 말은 다음과 같습니다.

위젯
화면의 부품입니다. 위젯마다 0x0191d0xx 형태의 번호가 있습니다.
캔버스
선택지 하나를 이루는 묶음입니다. sRGB와 AdobeRGB가 각각 캔버스 하나입니다.
포커스
지금 고르고 있는 선택지입니다. 포커스가 옮겨 가면 콜백 함수가 불립니다.
현재값·백업값
현재값은 설정 RAM의 한 바이트(sRGB 0, AdobeRGB 1)이고, 백업값은 화면을 열 때 따로 복사해 둔 바이트입니다.

색공간 행에서 선택지 화면이 열리기까지

상위 메뉴의 색공간 행에 이벤트 12가 들어오면 원본 코드가 색공간 화면(모드 0x53)을 열고, 선택지를 옮길 때마다 포커스 콜백이 설정 쓰기 함수를 부릅니다.

  1. 상위 메뉴에서 화면 열기 C3 행 이벤트 처리 함수는 이벤트 번호표를 따라 하위 메뉴 번호를 묻는 함수로 갑니다. 원본 모드 정보가 색공간 화면을 모드 0x53으로 정합니다. 커스텀 항목 13의 표에는 설정 ID 0xd7과 제목 문자열 배열이 들어 있습니다.
  2. 선택지 만들기 화면 구성 함수가 캔버스 세 개(전체, sRGB, AdobeRGB)를 만듭니다. 화면 모드 진입 과정에서 GUI 컴포넌트 26개가 만들어지고 초기 활성화까지 실행됩니다.
  3. 키 분배 UI 서비스는 이벤트를 먼저 GUI 컴포넌트에 건네고, 컴포넌트가 쓰지 않은 이벤트만 상위 처리기로 넘깁니다. 키 9와 10은 두 선택지를 서로 오가게 연결돼 있습니다.
  4. 포커스 콜백 캔버스는 이전 포커스를 끄고 새 선택지를 켭니다. 이 변화가 UI 서비스와 촬영 모드의 포커스 함수를 거쳐 0x80a84f88에 도착합니다.
주의

시험은 번역이 끝난 이벤트 번호에서 시작합니다. 원본 입력 함수가 스위치 번호표로 UI ID 3·8·9·10·11·12를 스위치 번호 5·10·11·12·13·14에 대응시키는 것은 확인했지만, 물리 버튼 스캔과 RTOS 큐는 실행하지 않았습니다. 이벤트 번호를 버튼 이름이나 다른 기종의 이벤트로 바꿔 읽지 않습니다.

고르는 즉시 기록하고, 취소하면 되돌립니다

현재값은 선택하는 순간 바뀝니다. 확정은 아무것도 더 쓰지 않고, 취소는 백업값을 다시 씁니다. 그래서 이 화면의 백업은 “보류값”이 아니라 “되돌리기용 사본”입니다.

화면을 열 때 원본 코드는 설정 ID 0xd7의 값을 읽어 백업 바이트에 복사합니다. 그 값이 1이면 AdobeRGB에, 아니면 sRGB에 첫 포커스를 둡니다. 포커스 콜백은 선택지가 무엇이든 설정 쓰기 함수를 부르므로, 같은 값이라도 첫 포커스에서 한 번 씁니다.

확정 이벤트 8은 설정을 더 쓰지 않고 상위 모드 0x23을 요청합니다. 취소 이벤트 3은 백업값을 다시 쓴 뒤 종료(인수 1)를 요청합니다. 다시 열면 RAM에 남은 값으로 첫 포커스가 정해졌습니다. [근거: findings.state · terminal, replay.cases]

설정 RAM 한 바이트와 파일 이름 규칙

설정 쓰기와 읽기는 같은 RAM 바이트를 씁니다. 선택이 바뀌면 파일 이름 접두사를 고르는 함수도 불리지만, 취소의 복원 함수는 그 함수를 부르지 않습니다.

설정 ID가 0x100보다 작으면 쓰기·읽기 함수는 bank 0의 메뉴 값 함수로 갑니다. 실제 주소는 기준 주소에 오프셋 두 개를 더한 한 바이트입니다. 쓰기는 값이 같아도 무조건 저장 명령(sb)을 실행합니다. 호출 기록과 실제 쓰기를 따로 세어 각각 {{stores}}회를 확인했고, 앞뒤 15바이트는 바뀌지 않았습니다.

파일 이름 접두사

포커스가 바뀌면 설정 쓰기 함수 뒤에 MediaService_SetDCFObjectFreeCharsStandard 0x803ff388가 이어집니다. 이 함수는 설정을 다시 읽어 0이면 모드 0, 0이 아니면 모드 1을 고른 뒤 하위 매체 API를 부릅니다. 설명서가 말하는 IMGPxxxx.JPG/_IMGxxxx.JPG 구분과 같은 방향입니다. [설명서 66쪽]

취소의 복원 함수 자체에는 이 호출이 없습니다. 다만 화면을 닫은 뒤 다른 경로가 접두사를 다시 정할 수 있으므로, 취소 뒤 실제 파일 이름이 이전 선택에 머문다고 단정하지 않았습니다. 실제 파일은 만들지 않았습니다. [근거: findings.storage · naming]

화면에 보이는 글자와 선택 표시의 연결

화면의 위젯 표에서 제목·선택지·안내문·확정·취소 글자의 문자열 자원을 찾았습니다. 이 글자를 실제로 그리는 과정은 다음 문서에서 이어집니다.

위젯 표 arcntColorSpaceSetModeTable 0x8080753c는 16바이트 레코드(위젯 ID, 종류, 인수 또는 자원 포인터, 네 번째 필드)로 이루어져 있습니다. 종류 9인 문자열 라벨 7개는 픽셀이 아니라 언어별 문자열 배열을 가리킵니다.

선택 표시는 캔버스가 활성화될 때 함께 켜집니다. 화면 구성 함수는 sRGB 쪽에 0x0191d00c·09·0d, AdobeRGB 쪽에 0x0191d011·0e·12를 활성 그리기 목록으로 붙입니다. GuiCanvas_Active 0x80aca908와 InActive 0x80aca3d4가 이 목록을 보이게 하거나 숨깁니다. 이 실행은 선택된 위젯과 컴포넌트 조회까지 확인했고, 보이기 값이나 픽셀은 비교하지 않았습니다. 이 목록이 실제로 그리는 선택 강조·선택 아이콘·안내문은 그리기 경로와 선택 강조의 픽셀에서 다룹니다. [근거: rendering]

K-3 Mark III의 공통 설계안과 다른 점

설정의 뜻(0 = sRGB, 1 = AdobeRGB)은 같지만, 값을 기록하는 시점이 다릅니다. Q7에 맞춘 화면이라면 “열 때 백업, 선택 때 즉시 기록, 확정 때 유지, 취소 때 복원, 다시 열 때 다시 읽기”로 만들어야 합니다.

K-3 Mark III 저장소는 세 기종에 공통으로 둘 UI 동작 이름(열기·선택·확정·취소)을 설계안으로 정리했습니다. 그 설계안의 “선택은 보류값만 바꾸고 확정할 때 바뀐 경우에만 쓴다”는 제안이며, Q7 원본의 즉시 쓰기·취소 복원과 다릅니다. 이벤트 번호, 설정 ID, 객체 배치, 자원 핸들은 기종마다 따로이므로 같다고 가정하지 않았습니다. 세 기종 비교 전체는 K-3 Mark III 저장소의 UI 이식 설계에 있습니다.

그리기이 화면의 라벨·캔버스·자원 연결별도 IconView 근거와 이 화면의 직접 근거를 구분

참조한 K-3 Mark III 파일은 공통 UI 설계안과 색공간 설정 재실행이며, 두 파일의 SHA-256은 근거 JSON의 sources에 고정했습니다. Q7의 결과로 K-3 Mark III의 미확정 화면 동작을 채우지 않았습니다.

한계와 재현 방법

  • 원본 입력부터 물리 화면까지 잇는 데는 스위치 스캔, 이벤트 큐 소비, 비동기 화면 갱신, 글자 래스터 출력이 더 필요합니다. 그중 갱신 요청과 픽셀 쓰기는 뒤의 네 문서가 따로 확인했습니다.
  • 설정 RAM과 DCF 호출은 별개입니다. 영구 저장, 매체 기록, 전원 재시작, 카메라 조작, 펌웨어 설치는 하지 않았습니다.
  • 자원 포인터·위젯 종류·정적 그리기 연결만으로는 이 화면의 최종 LCD 프레임, 픽셀 형식·stride, 다른 기종에 옮길 수 있는 자원 형식을 정할 수 없습니다.
  • 기종 비교는 기능의 뜻과 제안된 동작 이름만 빌렸습니다. Q7의 구현 세부로 K-3 Mark III나 K-3 II의 UI를 판단하지 않습니다.
