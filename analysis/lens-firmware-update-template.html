Q 마운트 렌즈 펌웨어 검증

Q7 본체 펌웨어(fwdc603p.bin) 안에는 SD 카드의 Q 마운트 렌즈 업데이트 파일(fwlq101.bin·fwlq102.bin)을 읽고 검증하는 코드가 들어 있습니다. 원본 MIPS 기계어를 Unicorn 에뮬레이터에서 실행해 두 실제 렌즈 펌웨어 파일과 대조했습니다.

이 문서에서

  1. 렌즈 펌웨어 파일 구조 (fwlq101.bin · fwlq102.bin)
  2. 실행 검증: ExecutionCheck 6사례
  3. 한계와 재현 방법
  4. 근거 파일과 참고 자료

핵심 요약

  • LensFirmwareUpdateService_GetCrc_BYTE({{GET_CRC_ADDR}})는 초기값 0x0000, 다항식 0x1021의 빅엔디언 CRC-16/CCITT를 계산합니다.
  • fwlq101.bin(01 STANDARD PRIME)과 fwlq102.bin(02 STANDARD ZOOM) 모두 크기 262,288바이트(0x40090)입니다. 끝 2바이트는 전체 파일([:-2])의 CRC(0x1ca0·0x1f20)이고 헤더 오프셋 0x30의 2바이트는 256KiB 본문(0x80..0x4007f)의 CRC(0x2668·0xfea2)입니다.
  • UserLensFirmwareUpdateExecutionCheck({{EXEC_CHECK_ADDR}})를 파일 I/O·LensDataServer 스텁과 함께 에뮬레이터로 실행한 결과 정상 2건은 1을, 렌즈 ID 불일치·파일 CRC 불일치·체크 바이트 0 아님·파일 열기 실패 4건은 0을 반환했습니다.
  • 실제 렌즈 통신선 전송과 렌즈 내부 플래시 기록(ComLensFirmUpdateWrite 이후)은 실기 렌즈가 없어 실행하지 않았습니다.

확인 코드 실행과 파일로 확인한 것

  • GetCrc_BYTE 원본 MIPS 명령의 CRC-16/CCITT 출력과 fwlq101.bin·fwlq102.bin 일치
  • UserLensFirmwareUpdateExecutionCheck 6사례 분기와 Printf_B 로그 메시지
  • 렌즈 펌웨어 파일의 128바이트 헤더, 256KiB LOM 본문, 16바이트 꼬리 구조

정적 분석 코드 읽기로 확인한 것

  • UserLensFirmwareUpdateExecution({{EXEC_ADDR}})이 본문 CRC(0x30)를 본체 전송 직전에 GetCrc_BYTE로 다시 대조하는 흐름
  • LensDataServer_GetLensFirmupFileNamePLC({{FILENAME_ADDR}})와 GetLensIdPLC({{LENS_ID_ADDR}})의 레지스터 규약

모델 에뮬레이션에서 대신 넣은 것

  • 장착된 렌즈의 ID와 파일 이름 응답(LensDataServer 스텁)
  • I:\fwlq*.bin 파일 열기·위치 이동·읽기와 힙 할당(FileX·Pool 스텁)

미확인 확인하지 않은 것

  • Q 마운트 렌즈 통신 버스 프로토콜과 렌즈 측 플래시 소거·기록 결과
  • 세이프 모드(LENS_SAFEMODE_FIRMUPDATE) 진입 조건과 실기 복구 동작

렌즈 펌웨어 파일 구조 (fwlq101.bin · fwlq102.bin)

두 파일은 128바이트 빅엔디언 헤더, 256KiB 본문(LOM), 16바이트 꼬리표로 나뉩니다.

{{LENS_ROWS}}
배포 파일 두 개에서 확인한 헤더·CRC 값
항목fwlq101.binfwlq102.bin

본문 시작 오프셋 0x80 뒤쪽 메타데이터 문자열 영역에는 두 파일 모두 PENTAX / INNOVATION!! 식별 문자열과 빌드 날짜 Oct 19 2011이 들어 있습니다. 버전 표시는 0049000.02와 0049010.00으로 나뉩니다.

실행 검증: ExecutionCheck 6사례

체크 바이트가 0이고 파일의 LENS_ID가 장착 렌즈와 같으며 파일 전체 CRC가 맞을 때만 1을 반환합니다.

에뮬레이터는 복원한 본체 ELF에서 UserLensFirmwareUpdateExecutionCheck를 그대로 실행하고 외부 함수 10개만 호출 경계에서 가로채 인수를 기록했습니다. 여섯 사례의 반환값과 로그 핵심 문자열은 아래와 같습니다.

{{CASE_ROWS}}
UserLensFirmwareUpdateExecutionCheck 에뮬레이션 6사례
사례장착 ID파일명반환핵심 로그

사전 검사를 통과해 실제 업데이트 함수 UserLensFirmwareUpdateExecution({{EXEC_ADDR}})으로 들어가면 카메라 배터리 확인 뒤 파일의 0x80 위치에서 LENS_LOM_SIZE(0x40000)바이트만 다시 읽어 GetCrc_BYTE로 계산합니다. 그 값이 헤더 0x30에서 저장한 값과 같을 때([LENSROM_CRC] AGREEMENT)만 렌즈 통신을 시작합니다.

한계와 재현 방법

이 검증은 본체 펌웨어 fwdc603p.bin에서 복원한 ELF와 실제 배포 렌즈 파일 fwlq101.bin·fwlq102.bin을 PC에서 대조한 결과입니다. 카메라와 렌즈 사이의 직렬 통신이나 렌즈 플래시 기록은 실행하지 않았습니다.

python -m unittest discover -s tests -p test_lens_firmware_update.py -v
python tools/check_lens_firmware_update.py --check analysis/lens-firmware-update.json
python tools/check_lens_firmware_update.py --firmware fwdc603p.bin --elf .private/main-expanded.elf \
  --lens fwlq101.bin fwlq102.bin --output .private/lens-check.json

근거 파일과 참고 자료

  • analysis/lens-firmware-update.json — 헤더 분석, CRC 대조, 에뮬레이션 6사례 기록

  • tools/build_lens_firmware_update_report.py — 이 문서 생성 스크립트
  • tests/test_lens_firmware_update.py — 공개 JSON 무결성 테스트
