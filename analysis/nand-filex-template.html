AppFb의 FileX 열기와 NAND 응답 경계

원본 AppFb가 FileX의 7번째 인수를 1로 구성했습니다. 합성 ID를 공급한 뒤 새 NAND op 6의 상태를 검사하는 분기 직전에 멈췄습니다.

AppFb가 구성한 FileX 호출

원본 AppFbLoadSection은 0x800e7a54, AppFbLoader는 0x800e7e24에서 _fx_media_open을 호출합니다. 두 호출의 지연 슬롯은 7번째 인수로 1을 저장합니다. 재현은 AppFcuMediaInfoInit(8)에 합성 ID, FF spare와 status 0을 공급했습니다. 등록한 registry header는 비재지정 제어 +0x14=0만 고정했습니다. +0x220/+0x398/+0x3a8/+0x3ac을 포함한 다른 바이트는 심벌 값으로 남겼습니다. 생산자가 반환한 상태를 복사한 뒤 별도로 AppFbLoader(1)에 진입했습니다. FileX의 인수는 원본 명령이 구성했습니다. 상위 FB/AFB 선택과 실제 부팅 순서는 이 시험에서 실행하지 않았습니다.

_fx_media_open_ex의 0x80066a68에서 열린 매체 목록 포인터를 읽기 직전에 멈춘 뒤 0을 제어값으로 공급했습니다. 다음 0x80066ac0 비교에서는 포인터가 새 media 주소와 다르면 해당 분기를 통과합니다. 앞선 할당·mutex·boot event 응답도 모델로 공급했습니다. 실행과 입력 모델

정적 상위 경로에서 AppLoadSegment는 header +0x398=0일 때 FB를 선택합니다. AppBootPrimary의 선택한 NAND 분기는 같은 바이트가 1일 때 eBootType=2, 그 외에는 1을 기록합니다. AppLoadSecondarySegments는 각각 AFB와 FB를 호출합니다. 두 선택 경로에 필요한 실제 +0x398과 선행 상태는 미확인입니다. 상위 선택 명령

임시 헤더 op 6과 정지 지점

후속 op 2에 합성 ID ecdc000100000000과 status 0을 재사용했습니다. 원본 TlMediaInit 경로는 media +0xbf4=1048576, +0xc18=0x105, +0xc14=8을 구성하고 FcuMediaInfoGetHeader(MEDIA,1,256,1)을 호출했습니다. 이 필드는 합성 입력에서 얻은 파서 결과입니다.

원본 0x800566f8의 할당 요청은 [0,0x400,0,0x80063a88,0x6cb]이며 복귀 주소는 0x80056700입니다. 새 op 6의 ABI는 [1,0x24700000,6,0,1,0,0x70000be8,16]입니다. 최종 지점에서 감시한 downstream 원본 읽기는 0x80056658의 registry mutex 포인터 한 건이었습니다. record, registry header, TEMP와 spare에서는 후속 원본 읽기를 관측하지 않았습니다. 할당·ABI·read trace

0x80055aacop 6 status가 0이면 spare 검사로 진행합니다. 0 이외면 실패 경로입니다. 재현은 이 분기와 지연 슬롯 직전에 멈췄습니다.
0x80055ab4 / 0x80055abcspare+5가 FF이면 op 4를 요청합니다. 그 외에는 위치에 stride를 더해 op 6을 다시 요청합니다.
0x80055c10 / 0x80055c28op 4가 성공하면 TEMP +0x14의 bit 31을 검사합니다. 설정돼 있으면 하위 31비트를 stride로 나눈 정수 몫을 두 번째 탐색의 시작 인덱스로 사용합니다.
0x80084120 / 0x80084128helper가 포인터를 반환하면 TEMP +0x200의 32비트를 MEDIA+0xc10으로 복사하고 TEMP 해제를 요청합니다.
0x80055608 / 0x80055628새 TL 생성과 native kind 1 lookup이 선행하면 record +0xc88을 복사해 분기합니다. +0xc8c는 지연 슬롯 0x8005562c에서 읽습니다.
0x80084ac0 / 0x80084af4partition helper가 registry header를 다시 조회해 +0x220/+0x314/+0x230/+0x310을 사용합니다.

요청 4의 0x800643dc와 요청 5의 0x80066bb4는 인수 7을 sentinel 0x80000000과 비교합니다. 이 범위에서 원본 AppFb의 1과 앞선 context 시험의 0은 같은 분기를 탑니다. 이후 kind 1 읽기가 성공하면 0x8008466c의 _fx_partition_offset_calculate에 서로 다른 index로 전달됩니다.

요청 5의 별도 sector 읽기가 성공한 경우에도 +0x1fe=0x55, +0x1ff=0xaa가 먼저 필요합니다. 첫 바이트가 0xe9이거나 첫 바이트 0xeb와 +2=0x90 조합이면 exFAT/FAT 형태 검사로 들어갑니다. 이 형태 검사에서 성공하면 table의 index 1 선택 없이 반환할 수 있습니다.

네 슬롯 table 경로에서 index 1은 0x1ce 슬롯을 선택합니다. type은 sector +0x1d2, offset은 LE32 +0x1d6, count는 LE32 +0x1da입니다. type 0 슬롯도 개수에 포함되며 offset과 count는 0으로 기록됩니다. 이 호출은 count 출력 포인터가 0이므로 parser 반환값 0만으로 유효한 partition이나 후속 읽기 성공을 확정할 수 없습니다. partition parser 원본

재현과 검증

초기 진단 실행은 분기 직전까지 도달한 뒤 SAT 질의에서 Windows 종료 코드 -1073741819로 중단됐습니다. 확정 실행은 SAT 질의를 수행하지 않았습니다. status가 독립된 32비트 BVS이며 원본 v0가 같은 심벌을 갖고 경로 제약이 0개임을 확인했습니다. 0과 1은 그 모델 정의에서 허용되는 대입 예입니다.
