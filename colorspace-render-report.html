01 / NATIVE REQUEST AND CONSUMER

생산한 메시지를 소비자에 그대로 전달한다

UiService_Refresh(1)이 만든 [0x80, 1, 0, 0] 메시지를 그대로 전달하면 원본 UiService_Perform이 UiService_DoRefresh(3)을 호출합니다. 위젯 갱신 뒤 쓰기 패스 0과 1을 거칩니다. 큐 전달과 동기화 API를 모델로 공급하고 명령 하나를 처리한 직후 중단하는 방식으로 네 번 실행했습니다. [R1: findings.refresh·replay]

02 / ACTIVE WIDGETS AND PALETTE INDICES

선택된 옵션에서만 강조·안내문을 그린다

두 옵션의 문구는 매번 그리지만 강조·선택 아이콘·안내문은 현재 선택된 옵션에서 나옵니다. 강조 영역은 논리 좌표 x=0, 폭 720, 높이 48이며 y=64 또는 112에 놓입니다. 원본 코드는 다섯 도형 요청에 팔레트 인덱스 0x4d·0x4d·0x4f·0x4f·0x4e를 지정합니다. 위젯 표의 인자 0x0f를 그대로 색 번호로 해석하면 맞지 않습니다. [R1: draw_order·highlight]

선택 강조 위젯은 0x0191d00c / 0x0191d011, 타입은 0x11입니다. 요청은 GuiSolidLine_WriteSolidLineInfo 0x80ad9104에서 관측했습니다. 다섯 요청의 겹침과 순서를 보존했으며 도형의 최종 래스터는 실행하지 않았습니다. [R2: frame_commands·refresh_cases]

03 / TEXT STAGING AND INDEXED PIXELS

텍스트 요청과 아이콘 픽셀을 구분한다

언어 표의 슬롯 0·1에 있는 영어·프랑스어 리소스를 사용했습니다. 원본 코드가 줄 수와 길이를 읽고 단위당 2바이트를 줄 버퍼에 옮긴 뒤 텍스트 API에 넘깁니다. 네 갱신에서 25줄의 좌표·길이·해시를 확인했습니다. 프랑스어 AdobeRGB 안내문은 y=280·328의 두 줄이고 영어는 y=280의 한 줄입니다. 글리프 모양은 아직 확인하지 않았습니다. [R1: labels·text·locale]

선택 아이콘 0x25의 논리 크기는 16×48이지만 비트맵은 21×48입니다. 원본 RLE 코드가 296바이트를 1,008바이트로 풀고 그중 0이 아닌 인덱스 330개를 각 선택 위치에 씁니다. 줄 간격 96바이트의 합성 버퍼 전체와 보호 영역을 비교했습니다. 투명한 0은 기존 값을 유지합니다. 이 줄 간격을 실제 LCD의 값으로 일반화할 수는 없습니다. [R2: pixel_cases]

원본 텍스트·아이콘 데이터는 로컬에 두고 주소·길이·해시를 게시했습니다. 픽셀 검사는 원본 리소스를 읽는 도구로 재현할 수 있습니다.

04 / DRAW, SHOW AND DISPLAY CONTEXT

버퍼 교체 요청 뒤에 장치 경계가 남는다

ScreenControl_Update에서 ScreenOsdLayer_Roll로 이어지는 원본 경로는 그리기 버퍼에 캐시 정리를 요청하고 이전 draw 버퍼를 새 show 버퍼로 지정합니다. 합성 버퍼 ID 17과 18은 네 갱신에서 서로 교대했습니다. 이후 표시 컨텍스트 선택과 LayerSetFrameBuffer·LayerMove 호출은 정적 코드로 연결되지만 이번 실행은 그 앞의 표시 버퍼 요청에서 멈췄습니다. [R1: findings.buffer·evidence]

캐시 요청은 합성 draw 주소와 960 × 480바이트 범위로 기록했습니다. 이는 시험용 GetBuffer 메타데이터이며 실제 패널 크기나 장치 stride를 입증하지 않습니다. 아이콘 단독 검사의 96바이트 stride와도 다른 조건입니다.

05 / K-3 MARK III UI PORT

표현을 옮기기 전에 선택 확정 방식을 정한다

K-3 Mark III 자료에서 Color Space 행은 텍스트 ID 0x1f6·0x1f7과 스타일별 아이콘을 사용하며 pending 선택값을 거칩니다. Q7은 초점 이동 때 설정을 즉시 쓰고 확인 때 유지하며 취소 때 되돌립니다. 동작 이름은 대응시킬 수 있어도 숫자 ID·리소스 구조·팔레트·이벤트를 그대로 옮길 근거는 없습니다. UI 재구현에서는 이 선택 확정 방식의 차이를 먼저 정해야 합니다.
