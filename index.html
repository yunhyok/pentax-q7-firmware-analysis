Q7 v1.01의 원본 식별과 파일 구조 분석을 마쳤습니다. 내장 ELF 12개에서 32비트 little-endian MIPS 헤더를 확인했으며 ThreadX·FileX 식별 문자열과 심볼을 찾았습니다. 이 보고서는 후속 함수 분석을 시작하기 위한 기준 자료입니다.

01 / IDENTITY

공식 v1.01 파일과 바이트 단위 일치

제공된 파일을 리코 공식 q7_101.zip의 fwdc603p.bin과 직접 비교했습니다. 두 파일은 크기와 SHA-256이 같고 모든 바이트가 일치합니다. 따라서 이번 분석 대상을 공식 배포 v1.01과 연결할 수 있습니다. 이는 배포 파일의 동일성 확인이며 카메라의 업데이트 서명 검증을 대신하지 않습니다. [P1] [S1]

02 / METHOD

검증 순서는 이어가고, 형식은 다시 확인

K-3 Mark III에서 사용한 해시 고정, 구조 검증, 주소 매핑, 재현 검사 순서를 따랐습니다. 다만 파일 형식은 다릅니다. K-3 분석 도구의 LZ 해제기를 수정 없이 적용하면 Q7의 0x80에서 실패합니다. 이 결과는 해당 시작 위치와 형식이 맞지 않는다는 뜻이며, Q7 전체에 압축 데이터가 없다는 뜻은 아닙니다. [E1: k3_lz_probe] [B1]

03 / FILE LAYOUT

12개 ELF가 가리키는 파일 구간

ELF 서명은 13곳에서 검출됐습니다. 헤더와 파일 참조 범위를 검사한 결과 12곳이 이번 파서의 검사를 통과했습니다. 나머지 0x1DC2C4는 ELF 식별 바이트 뒤에 DllMutex 문자열이 이어져 제외했습니다. 아래 막대는 각 ELF가 참조하는 마지막 바이트까지의 범위입니다. 업데이트 컨테이너의 실제 파티션 경계나 플래시 배치를 확정한 결과는 아닙니다. [E1: elfs, rejected_candidates]

검사를 통과한 ELF는 모두 ELFCLASS32, ELFDATA2LSB, EM_MIPS 값을 갖습니다. ET_EXEC 10개와 ET_REL 2개를 구분했습니다. ET_REL의 심볼 값은 섹션을 기준으로 해석해야 하며, 실제 메모리 주소로 옮기려면 로더와 재배치 처리를 확인해야 합니다. 일부 ELF는 섹션 테이블이 없는데 e_shstrndx가 13으로 남아 있어 경고를 기록했습니다. [E1: warnings] [S2]

04 / RTOS & SYMBOLS

ThreadX·FileX를 조사할 지점 확보

ThreadX LX4180/Green Hills와 FileX LX4180/Green Hills 문자열이 원본 파일에 남아 있습니다. 첫 ELF에서는 _tx_initialize_kernel_enter, _tx_thread_create, _tx_thread_schedule, _fx_media_open 심볼도 확인했습니다. ThreadX·FileX 계열 코드가 포함돼 있다는 근거입니다. 이 정보만으로 물리 SoC 모델이나 카메라에서 실행되는 모든 구성 요소를 확정할 수는 없습니다. [E1: markers, selected_symbols]

첫 ELF의 심볼 테이블에는 2,121개 항목이 있으며, 이 중 정의된 STT_FUNC 항목은 1,437개입니다. 전체 ELF의 합계는 2,569개 심볼 항목과 1,504개 정의된 함수 심볼 항목입니다. 같은 함수를 중복해 나타낼 수 있으므로 고유 함수 수로 세지 않았습니다. 심볼 이름은 조사할 지점을 알려 주지만 함수의 실제 동작까지 입증하지는 않습니다. [E1: symbol_count] [S3]

05 / BYTE DISTRIBUTION

파일 전체의 엔트로피 분포

원본을 65,536바이트 창으로 나누어 Shannon 엔트로피를 계산했습니다. 값이 높은 구간은 압축 데이터나 영상 자원 등을 조사할 후보가 됩니다. 엔트로피만으로 암호화 여부를 판정하지 않았습니다. 마지막 창은 파일에 남은 바이트만 계산했습니다. [E1: entropy_windows]

06 / REPRODUCIBILITY

같은 파일로 다시 검사하기

Python 3.10 이상에서 표준 라이브러리만 사용합니다. 원본 파일은 읽기 전용으로 다루며 결과는 새 경로에 씁니다.

python -m unittest discover -s tests -v
python tools/pentax_lz.py --self-test
python tools/inspect_q7.py "path/to/fwdc603p.bin" --output .private/recheck.json --private-dir .private/recheck-elf
python tools/verify_report.py --firmware "path/to/fwdc603p.bin"
python tools/build_report.py

검증 도구는 파서의 합성 입력 테스트, 공개 근거의 일관성, 보고서 생성 결과와 로컬 링크를 확인합니다. 원본을 지정하면 공개 측정값 전체를 다시 계산해 비교합니다. 분석기 · 테스트 · 보고서 검사

현재 REA 세션에서는 펌웨어용 Binwalk·Unblob 공급자와 네이티브 디컴파일 공급자를 사용할 수 없습니다. 이번 결과는 Python 표준 라이브러리로 읽은 파일 바이트와 ELF 메타데이터에 근거합니다. REA의 함수 분석 결과나 실기 실행 결과로 제시하지 않습니다. 업데이트 체크섬, 서명 검증, 플래시 쓰기 절차, AF·셔터·JPEG·색 처리 함수의 동작은 아직 확인하지 않았습니다. [T1]

07 / NEXT QUESTIONS

다음은 코드 참조와 로더 구조

다음 분석에서는 첫 ELF의 진입점과 ThreadX 초기화 심볼부터 호출 관계를 확인합니다. 이어 섹션 정보가 없는 ELF의 로드 구간과 업데이트 컨테이너 경계를 조사한 뒤, AF·셔터·JPEG·화이트밸런스 관련 문자열을 코드 참조와 연결합니다. K-3의 ARM 주소나 함수 의미를 Q7에 그대로 적용하지 않습니다.
